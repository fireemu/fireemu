## 테스트할 수 있는 것

- 푸시, 필터, 순서 키, StreamingPull, 스냅샷, seek를 포함한 [Pub/Sub 토픽, 구독, 전달](#cloud-pubsub).
- 프로덕션의 IAM 권한 부여를 포함하거나 포함하지 않는 [데드 레터 전달](#데드-레터-토픽).
- 자격 증명이 있거나 없는 [Pub/Sub 요청](#인증).
- [`onCustomEventPublished` 함수로 전달되는 커스텀 이벤트](#eventarc).
- [`onTaskDispatched` 함수로 전달되는 작업](#cloud-tasks).

## 연결

| 서비스 | 기본 주소 | 환경 변수 | 시작 조건 |
|---|---|---|---|
| Cloud Pub/Sub | `127.0.0.1:8085` | `PUBSUB_EMULATOR_HOST` | 구성된 경우: `firebase.json`의 `emulators.pubsub`, `daemon.pubsubPort`, `--pubsub-port`, 또는 `--only pubsub` |
| Eventarc | `127.0.0.1:9299` | `CLOUD_EVENTARC_EMULATOR_HOST` | Functions 코드베이스가 로드된 경우 |
| Cloud Tasks | `127.0.0.1:9499` | `CLOUD_TASKS_EMULATOR_HOST` | Functions 코드베이스가 로드된 경우 |

`fireemu exec`는 Google Cloud 클라이언트 라이브러리가 읽는 `PUBSUB_EMULATOR_HOST`를 설정합니다([환경 변수](../../reference/environment-variables/) 참조). Fireemu는 `CLOUD_EVENTARC_EMULATOR_HOST`와 `CLOUD_TASKS_EMULATOR_HOST`를 해당 리스너를 시작할 때 설정합니다.

## Cloud Pub/Sub

토픽, 구독, 게시, 풀(pull)과 확인 응답(acknowledgement), 푸시 전달, 필터, 순서 키, 데드 레터 토픽, StreamingPull, 스냅샷, seek를 지원합니다. 지원하지 않는 항목은 [프로덕션과의 차이](#프로덕션과의-차이)를 참조하십시오.

### 토픽 메시지 저장 정책

`profile = "emulator"`에서 토픽의 `messageStoragePolicy`(`allowedPersistenceRegions`와 `enforceInTransit`)는 공식 에뮬레이터와 마찬가지로 보낸 그대로 저장되고, get과 list로 반환되며, `UpdateTopic`(`updateMask`를 사용하는 REST `PATCH`, 마스크는 `messageStoragePolicy`와 그 두 멤버)으로 변경됩니다.

- 알 수 없는 리전 목록, 중복된 리전 목록, 빈 리전 목록, 빈 정책은 모두 그대로 유지됩니다.
- 정책을 지정하지만 값을 보내지 않는 마스크는 정책을 제거합니다.
- 아무것도 강제되지 않습니다. 메시지는 리전에 따라 라우팅되지 않습니다.

`strict` 프로필은 이 필드를 `UNIMPLEMENTED`(REST 501)와 설명으로 거부합니다. 프로덕션은 모든 리전을 Google Cloud의 Pub/Sub 리전 목록과 대조하여 검사하며(`no-such-region1`에는 `INVALID_ARGUMENT`로 응답하고 `us-central1`은 수락했습니다), Fireemu에는 대조할 출처가 명시된 그 목록의 사본이 없습니다. `strict`에서는 이 필드를 생략하거나, 유지하려면 emulator 프로필을 선택하십시오.

### 토픽 키 이름과 태그

`profile = "emulator"`에서 토픽의 `kmsKeyName`과 `tags`는 보낸 그대로 저장되며, 검증이나 강제 없이 REST와 gRPC로 반환됩니다. `UpdateTopic`은 `kms_key_name`을 교체하거나 지울 수 있으며, 태그는 변경할 수 없습니다.

strict 프로필은 이 필드를 거부합니다. 프로덕션의 검증이 Fireemu에는 없는 Cloud KMS와 Resource Manager의 인벤토리 및 권한에 의존하기 때문입니다. 공식 에뮬레이터 0.8.35는 이 값을 검증 없이 저장하고 모든 업데이트 마스크를 거부하며, 프로덕션 동작은 기록되지 않았습니다.

### 데드 레터 토픽

`strict`에서 `maxDeliveryAttempts`를 소진한 메시지는 프로젝트 번호와 IAM 권한 부여 없이, 프로덕션이 추가하는 메타데이터 속성과 함께 데드 레터 토픽으로 전달됩니다.

프로덕션은 Pub/Sub 서비스 에이전트가 구독에 대해 `roles/pubsub.subscriber`를, 데드 레터 토픽에 대해 `roles/pubsub.publisher`를 보유한 뒤에야 전달합니다. `SetIamPolicy`를 통해 같은 권한 부여를 요구하려면 `pubsub.deadLetterAuthorization`을 `"iam"`으로 설정하십시오(또는 `productionExact`를 사용하거나 `pubsub.projectNumbers`를 지정). 그러면 시작 배너에 권한을 부여할 서비스 에이전트가 표시됩니다.

### REST 프런트엔드의 캐시된 404 (`pubsub.restNegativeCache`)

프로덕션의 REST 프런트엔드는 구독이 생성된 직후 구독의 `GET`에 캐시된 `404`로 응답할 수 있습니다. `pubsub.restNegativeCache`는 모든 프로필에서 기본값이 `"off"`이며, `productionExact`는 이를 선택하지 않습니다.

이 키를 `"production"`으로 설정하면(strict 프로필에서만) `GET` 또는 `PATCH`의 실제 `404`가 **같은 연결**에서 같은 구독의 `GET`, `PATCH`, `DELETE`에 대한 캐시 항목을 활성화하는 것으로 모델링되어, `PATCH`나 `DELETE`가 실행되지 않습니다.

이 모델이 하는 일과 아직 열려 있는 부분은 다음과 같습니다.

- **윈도.** 경계는 선명하지 않습니다. 한 기록에서는 10.25초부터 10.50초까지의 모든 읽기가 적중하지 않았고, 다른 기록에서는 같은 경과 시간의 미적중 옆에서 10.40초에서 10.50초에 적중했으며, 이전 기록에서는 10.20초까지 적중했습니다. 프로덕션은 10.2초에서 10.5초 부근에서 비결정적이며, fireemu의 결정적인 10.35초 윈도는 알려진 차이입니다.
- **404 이전의 `GET` 200.** 404 일곱 초 전의 `GET` 200은 v5의 두 실행 모두에서 해당 404를 면제했으며, 4초와 13초는 아직 열려 있습니다. 이 모델은 윈도 안의 `GET` 200을 면제합니다.
- **DELETE와 생성된 적 없는 이름.** DELETE 404의 활성화와, 생성된 적 없는 이름에 대한 활성화는 아직 열려 있습니다. 이 모델은 DELETE에서는 활성화하지 않고, 생성된 적 없는 이름에서는 활성화합니다.
- **항목에서 절대 응답하지 않는 것.** 다른 연결, `:pull` 또는 `:getIamPolicy`, 스냅샷, 토픽, gRPC, 쿼리 문자열이 있는 요청.
- **활성화하지 않는 것.** 실패한 생성과, `404`로 응답하는 `:seek`.

만료는 데몬의 논리 시계를 사용합니다. 시계가 멈춰 있으면 캐시된 404에서 복구하기 위해 시계를 10.35초 윈도 이후로 앞당기거나, 다른 연결을 사용하거나, 캐시를 비활성화하십시오.

### 인증

`strict`에서는 자격 증명이 없는 요청이 수락되므로, 자격 증명 없이 `PUBSUB_EMULATOR_HOST`를 사용하는 클라이언트가 동작합니다. 자격 증명을 제시하는 요청은 검사되는데, Fireemu는 실제 Google OAuth 토큰을 오프라인으로 검증할 수 없으므로 그러한 요청은 401로 거부됩니다. 예를 들어 `NoCredentialsProvider`를 사용하는 Java 클라이언트처럼, 에뮬레이터에는 자격 증명이 없는 클라이언트를 사용하십시오.

자격 증명이 필요한 테스트에는 로컬 픽스처 bearer 토큰을 설정하십시오. 그러면 엔드포인트는 정확히 그 값의 `Authorization: Bearer <token>`만 수락하고, 프로덕션과 마찬가지로 자격 증명이 없는 요청을 거부합니다.

# Require this non-empty local bearer token for strict-profile Pub/Sub requests.

임의로 만든 값을 사용하고, 프로덕션 자격 증명을 절대 재사용하지 마십시오.

## Eventarc

Functions 코드베이스가 로드되면 Fireemu는 `127.0.0.1:9299`에서 Eventarc 리스너를 시작하고 `CLOUD_EVENTARC_EMULATOR_HOST`를 설정합니다. `onCustomEventPublished`로 선언된 함수는 해당 채널에 게시된 이벤트를 받습니다.

Admin SDK는 게시하기 전에 항상 자격 증명에 액세스 토큰을 요청하는데, CI에는 Google 자격 증명이 없습니다. 앱에 가짜 자격 증명을 제공하십시오.

```js
import { initializeApp } from 'firebase-admin/app';
import { getEventarc } from 'firebase-admin/eventarc';

const app = initializeApp({
  projectId: 'demo-app',
  credential: { getAccessToken: async () => ({ access_token: 'owner', expires_in: 3600 }) },
});
await getEventarc(app).channel('locations/us-central1/channels/firebase').publish({
  type: 'com.example.thing.done',
  source: 'https://example.com/things',
  data: { id: 'e1' },
});
```

기본적으로 리스너는 공식 에뮬레이터가 검사하지 않는 것과 마찬가지로 자격 증명을 검사하지 않습니다(`eventarc.authentication: "permissive"`). `"production"`(또는 `productionExact`)에서는 누락되었거나 형식이 잘못되었거나 JWT 형태인 bearer가 프로덕션의 401로 거부됩니다.

## Cloud Tasks

Functions 코드베이스가 로드되면 Fireemu는 `127.0.0.1:9499`에서 Cloud Tasks 에뮬레이터를 시작하고 `CLOUD_TASKS_EMULATOR_HOST`를 설정합니다. 태스크 큐 함수(`onTaskDispatched`)는 자신을 위해 큐에 넣어진 작업을 속도 제한과 재시도 구성과 함께 받습니다. 작업의 `scheduleTime`은 `strict`에서 작업을 보류합니다. 대기 중인 작업, **Run now**, 가상 시계는 [태스크 큐](../functions/#태스크-큐)를 참조하십시오.

## 프로덕션과의 차이

### 지원되지 않는 Pub/Sub 기능

스키마, BigQuery 및 Cloud Storage 구독 전달, 그리고 `UpdateTopic` 같은 일부 API는 지원되지 않습니다. emulator 프로필에서 `UpdateTopic`은 [토픽 메시지 저장 정책](#토픽-메시지-저장-정책)과 [토픽 키 이름과 태그](#토픽-키-이름과-태그)에서 설명한 필드를 변경합니다.

### `strict` 프로필이 거부하는 필드

- `messageStoragePolicy`: [토픽 메시지 저장 정책](#토픽-메시지-저장-정책)을 참조하십시오.
- `kmsKeyName`과 `tags`: [토픽 키 이름과 태그](#토픽-키-이름과-태그)를 참조하십시오.

### 기타 차이

- 데드 레터 전달은 요청하지 않는 한 IAM 권한 부여가 필요하지 않습니다. [데드 레터 토픽](#데드-레터-토픽)을 참조하십시오.
- REST 네거티브 캐시는 기본적으로 꺼져 있습니다. 켜져 있을 때 10.35초 윈도는 결정적이지만 프로덕션의 윈도는 그렇지 않습니다. [REST 프런트엔드의 캐시된 404](#rest-프런트엔드의-캐시된-404-pubsubrestnegativecache)를 참조하십시오.
- 실제 Google OAuth 토큰을 가진 Pub/Sub 요청은 토큰을 오프라인으로 검증할 수 없으므로 `strict`에서 401로 거부됩니다. [인증](#인증)을 참조하십시오.
- Eventarc 리스너는 `eventarc.authentication`이 `"production"`이 아닌 한 자격 증명을 검사하지 않습니다. [Eventarc](#eventarc)를 참조하십시오.
