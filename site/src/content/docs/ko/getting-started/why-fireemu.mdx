Fireemu는 Firebase로 만든 애플리케이션을 테스트하기 위한 로컬 에뮬레이터입니다. 프로덕션 Firebase의 동작과 일치시키는 것을 목표로 하므로, 실제 Firebase 프로젝트를 사용하지 않고 로컬과 CI에서 테스트할 수 있습니다.

Firebase Local Emulator Suite는 Google의 공식 도구입니다. Fireemu보다 더 많은 제품을 다루며, 그중 하나가 필요하다면 올바른 선택입니다. Fireemu의 목표는 더 좁습니다. CI와 개발자 컴퓨터에서 얻은 결과가 프로덕션에서도 그대로 통하는 테스트입니다.

## Local Emulator Suite와의 비교

| 항목 | Local Emulator Suite (`firebase-tools` 15.28.2) | Fireemu |
|---|---|---|
| 유지 관리 | Google | Fireemu 프로젝트 |
| 제품 | Firestore, Realtime Database, Authentication, Cloud Storage, Functions, Pub/Sub, Eventarc, Cloud Tasks, Hosting, App Hosting, Data Connect, Extensions | Firestore, Authentication, Cloud Storage, Functions, Pub/Sub, Eventarc, Cloud Tasks, Realtime Database와 Hosting(둘 다 부분 지원), App Check. App Hosting과 Data Connect는 아직 지원하지 않고, Extensions는 계획에 없음([상태](../../#supported-products)) |
| 런타임 | Firestore와 Realtime Database 에뮬레이터는 Node.js CLI 옆에서 Java(`java -jar`) 프로세스로 실행 | npm 패키지로 설치하고 시작하는 단일 네이티브 바이너리(Node.js 20 이상) |
| 시작 시간과 메모리, Firestore만 | SDK가 Firestore를 사용할 수 있을 때까지 3,043 ms, 유휴 메모리 390 MiB(PSS) | `emulator` 프로필: 140 ms, 11 MiB. GitHub Actions Linux 러너에서 커밋 `f3b942c`의 `standard` 실행 1회, JDK 21.0.8, 측정한 다섯 쌍([조건](../../compatibility/performance/)) |
| 복합 인덱스가 정의되지 않은 쿼리 | 쿼리 실행 | `strict` 프로필(기본값): 프로덕션처럼 콘솔 링크와 함께 `FAILED_PRECONDITION`. `firestore.missingIndexes = "report"`이면 쿼리를 실행하고 누락된 인덱스를 보고. `emulator` 프로필: Local Emulator Suite처럼 쿼리 실행 |
| TOTP 다단계 인증 | Authentication 에뮬레이터는 전화(SMS) 2단계 인증 요소를 받아들이며, 다른 요소 유형에는 `MFA provider not supported!`로 응답 | 두 프로필 모두: 프로젝트의 MFA 구성을 통한 TOTP와 SMS |
| App Check | App Check 에뮬레이터 없음 | 두 프로필 모두: 디버그 토큰 교환, 그리고 Authentication, Firestore, Storage, 호출 가능 함수에 대한 적용. 증명(attestation) 제공자 없음([자세히](../../products/app-check/)) |

테스트 결과를 바꾸는 더 많은 차이와 각각에 대한 프로덕션의 응답은 [호환성 표](../../compatibility/#fireemu-공식-에뮬레이터-프로덕션)에 있습니다.

## Fireemu가 추가하는 것

Local Emulator Suite는 Firebase 앱의 로컬 개발을 위해 만들어졌습니다. Fireemu는 프로덕션이 적용하며 CI에서 중요한 검사를 추가합니다.

- **프로덕션이 요구하는 구성.** `firestore.indexes.json`에 선언되지 않은 복합 인덱스가 필요한 Firestore 쿼리는 `strict`에서 거부됩니다.
- **공식 에뮬레이터가 제공하지 않는 기능.** TOTP 다단계 인증, 디버그 토큰을 사용하는 App Check, 그리고 `strict`에서의 `beforeEmailSent` 차단 함수.
- **테스트 실행 조건의 제어.** 임의의 시작 시각을 설정하고 가상 시계를 움직여, 실제 일정을 기다리지 않고 예약 함수를 실행합니다.

## 프로덕션 우선

공식 에뮬레이터와 프로덕션 Firebase가 다를 때, Fireemu는 기본 `strict` 프로필에서 프로덕션을 따르고 그 차이를 기록합니다. 예외는 아래에서 설명하는 개발용 기본값입니다. 응답은 프로덕션의 문구와 상태 코드를 유지하므로, 테스트에서 애플리케이션이 처리하는 오류는 배포 후에 마주칠 오류와 같습니다.

각 동작은 실제 Firebase 프로젝트에서 수집한 녹화와 대조해 검사합니다. 이 방식으로 비교한 영역은 <VerifiedAreaCount />개입니다. [호환성 표](../../compatibility/)에는 각 영역과 그 범위, 다루는 조건의 수가 나열되어 있고, [제한 사항](../../compatibility/limitations/)에는 다루지 않는 것이 나열되어 있습니다. Fireemu는 둘이 다를 때 프로덕션을 따르지만, 프로덕션과 동등하다고 주장하지는 않습니다.

### 개발용 기본값

프로덕션의 일부 동작은 테스트에서 비용이 큽니다. 프로덕션은 서명된 토큰, 서명 키, 또는 Admin API 호출로 켜는 기능을 요구합니다. 이런 항목마다 Fireemu는 프로덕션과 의도적으로 다르면서도 별도 설정 없이 동작하는 개발용 기본값을 유지합니다. 정확히 재현하면 더 많은 버그를 찾지 못한 채 테스트만 느려지기 때문입니다. 각 항목은 문서화되어 있으며 고유한 설정이 있습니다. 고급 스위치인 `productionExact`는 이 모두에 대해 프로덕션의 동작을 복원합니다. [Fireemu가 의도적으로 프로덕션과 다른 부분](../../guides/profiles/#fireemu가-의도적으로-프로덕션과-다른-부분)을 참고하십시오.

## 테스트를 위한 설계

- **CI용 명령 하나.** `fireemu exec -- npm test`는 에뮬레이터를 시작하고, 에뮬레이터 환경 변수를 설정한 채 테스트를 실행하고, 모든 것을 중지한 뒤 테스트 명령의 종료 상태를 반환합니다.
- **`firebase.json`을 재사용.** 규칙, 인덱스, Functions 코드베이스, 포트는 시작할 때마다 그 파일에서 읽습니다.
- **거부 이유를 설명.** Security Rules의 거부마다 평가된 조건과 그 결과가 출력됩니다.
- **독립적인 테스트 월드.** `fireemu/testing` 도우미는 병렬 통합 테스트를 위해 자체 시계, 규칙, Functions, 데이터를 가진 격리된 에뮬레이터 인스턴스를 시작합니다.
- **단일 네이티브 바이너리.** 측정한 수치와 조건은 [성능](../../compatibility/performance/)을 참고하십시오.

## Fireemu가 아닌 것

Fireemu는 실제 할당량 계산, 결제, IAM, 조직 정책, 리전과 네트워크 차이, 서비스 롤아웃을 재현하지 않습니다. 로컬 성능은 프로덕션의 지연 시간을 예측하지 않습니다. [제한 사항](../../compatibility/limitations/)을 참고하십시오.

## 프로덕션 확인은 유지하십시오

Fireemu는 아직 개발 중입니다. 애플리케이션이 사용하는 기능과 핵심 워크플로에 대해 같은 테스트를 Fireemu와 전용 Firebase 테스트 프로젝트(운영 프로젝트가 아닌)에 대해 실행하고, CI에서 Fireemu만 믿기 전에 결과를 비교하십시오.
