프로파일은 Fireemu가 누구의 동작을 따를지 선택합니다. 프로덕션 Firebase(`strict`, 기본값) 또는 공식 에뮬레이터(`emulator`)입니다. 두 프로파일 모두 테스트를 별도 설정 없이 실행할 수 있도록 일부 기본값이 의도적으로 프로덕션과 다릅니다. `productionExact`를 사용하면 이 기본값들이 프로덕션의 동작으로 전환됩니다.

## 프로파일 선택

| 프로파일 | 동작 |
|---|---|
| `strict` | 지원 범위 안에서 프로덕션 Firebase의 동작과 제약을 최대한 그대로 따릅니다. 기본값이며, 공식 에뮬레이터에서 마이그레이션하는 경우를 포함해 이 프로파일을 권장합니다. |
| `emulator` | 공식 에뮬레이터의 고정된 버전(`firebase-tools` 15.28.2)의 동작을 따릅니다. 공식 에뮬레이터와의 정합성을 확인할 때, 예를 들어 추가 테스트 대상으로만 사용하십시오. 마이그레이션에는 필요하지 않습니다. |

`emulator` 프로파일은 프로덕션이 거부하는 동작을 허용하므로, 테스트가 이 프로파일에서는 통과하고 프로덕션에서는 실패할 수 있습니다. 테스트에는 `strict`를 사용하십시오.

```toml
# Compatibility profile: "strict" or "emulator".
profile = "strict"
```

## 구성 선택

- **대부분의 프로젝트:** 개발용 기본값을 사용하는 `strict`. 키나 설정 호출 없이 테스트가 실행되면서도 프로덕션의 검증, 거부, 오류 형태를 그대로 따릅니다.
- **릴리스 전, 또는 별도의 CI 작업:** [`productionExact: true`](#fireemu가-의도적으로-프로덕션과-다른-부분)를 적용한 `strict`. 서명되지 않은 토큰처럼 개발용 기본값이 통과시키는 문제를 잡아냅니다.
- **공식 에뮬레이터 확인:** `emulator`. 추가 테스트 대상으로만 사용합니다.

## Fireemu가 의도적으로 프로덕션과 다른 부분

Fireemu의 목표는 프로덕션과 일치하는 것입니다. 다만 일부 프로덕션 동작은 테스트에 설정 작업만 더할 뿐입니다. 프로덕션은 서명된 토큰과 서명 키를 요구하고, Admin API 호출로 기능을 활성화해야 하며, 한 시간을 기다려야 하는 경우도 있습니다. 이를 그대로 복제하면 더 많은 버그를 잡지는 못하면서 CI와 개발자 머신에서 Fireemu를 사용하기가 더 어려워집니다.

이러한 동작에 대해서는 두 프로파일 모두 설정 없이 동작하는 개발용 기본값을 사용합니다. 각각 고유한 설정 키가 있고 아래 표에 나열되어 있으므로, 프로덕션과의 이런 차이는 모두 문서화된 선택입니다.

### productionExact로 프로덕션 동작 켜기

이 모든 항목에 프로덕션의 동작을 한꺼번에 적용하려면 `productionExact`를 `true`로 설정합니다(`strict` 프로파일 전용). 명시적으로 지정한 설정이 여전히 우선합니다.

<Tabs syncKey="config-format">
<TabItem label="TOML">

```toml
# Configuration schema version: 1.
schemaVersion = 1
# Compatibility profile: "strict" or "emulator".
profile = "strict"
# Use production behavior for development defaults: true or false; requires strict.
productionExact = true

[auth]
# Accept unsigned emulator custom tokens: true or false.
allowUnsignedCustomTokens = true
```

</TabItem>
<TabItem label="JSON">

```json
{
  "schemaVersion": 1,
  "profile": "strict",
  "productionExact": true,
  "auth": {
    "allowUnsignedCustomTokens": true
  }
}
```

</TabItem>
</Tabs>

### 개발용 기본값

| 개발용 기본값 | 설정 | `productionExact` 적용 시 |
|---|---|---|
| 서명되지 않은 에뮬레이터 커스텀 토큰을 허용합니다 | `auth.allowUnsignedCustomTokens` | 거부합니다 |
| Firestore, Storage, Realtime Database의 Security Rules가 `@firebase/rules-unit-testing`의 서명되지 않은 목(mock) ID 토큰(`authenticatedContext()`, 클라이언트 SDK의 `mockUserToken`)을 허용합니다 | `auth.allowUnsignedIdTokens` | 프로덕션이 서명되지 않은 토큰을 거부하므로 목 토큰 폴백이 비활성화됩니다. 일반적인 검증을 통과하는 fireemu 발급 토큰은 계속 허용됩니다 |
| 공식 에뮬레이터가 제공하는 방식과 같이, 규칙 파일이 없는 Realtime Database 인스턴스는 모든 요청에 열려 있습니다 | `database.defaultAccess` (`"open"`) | `"locked"`: 프로덕션이 잠금 모드의 새 데이터베이스에 관리자만 허용하는 것과 같이, 에뮬레이터의 `owner` 자격 증명만 읽고 쓸 수 있습니다 |
| Hosting이 기본 `Cache-Control` 없이 파일을 제공하므로, 브라우저에서 수정한 파일이 즉시 표시됩니다 | `hosting.cacheControl` (`"none"`) | `"production"`: Hosting 프로덕션과 같이, `headers` 규칙에서 `Cache-Control`을 지정하지 않은 파일에 `Cache-Control: max-age=3600`을 추가합니다(strict 프로파일 전용) |
| Hosting의 지역화된 콘텐츠가 `X-Country-Code` 헤더와 `firebase-country-override` 쿠키를 따르므로, 국가별 콘텐츠를 테스트할 수 있습니다 | `hosting.clientCountry` (`"honoured"`) | `"ignored"`: 프로덕션은 엣지에서 국가를 결정하므로 둘 다 아무것도 선택하지 않습니다(strict 프로파일 전용) |
| 한 코드베이스의 모든 함수가 하나의 러너 프로세스에서 실행되므로, 함수들이 모듈 그래프를 공유하고 ID 변수는 가장 나중에 시작된 호출을 가리킵니다 | `functions.isolation` (`"codebase"`) | `"function"`: 함수마다 하나의 러너 프로세스가 첫 트리거 시점에 시작되며, 각각 자체 ID, 시크릿, 모듈 그래프를 가집니다. 시작된 함수당 약 120 MiB의 메모리가 들고, 첫 호출에 콜드 스타트가 발생합니다 |
| Auth 차단 함수가 에뮬레이터 토큰을 사용합니다 | `functions.authBlockingToken` (`"emulated"`) | `"production"`은 서명된 토큰을 전달하며 Python 러너는 SDK 규칙에 따라 이를 검증합니다. Node 함수는 같은 프로덕션 형태의 토큰을 받지만 검증하지 않으므로 이전과 동일하게 동작합니다. `strict` 필요 |
| 완료된 Cloud Tasks 작업의 이름을 즉시 다시 쓸 수 있습니다 | `functions.taskNameReuse` (`"immediate"`, `emulator` 프로파일에서는 `"retained"`) | `"production"`은 Cloud Tasks 문서에 따라 최대 3600초 동안 해당 이름을 거부합니다("existed too recently"). 완료된 이름의 이력은 모든 큐를 합쳐 이름 65,536개와 큐 및 작업 이름 텍스트 8 MiB로 제한되며, 두 한도 중 하나를 넘으면 3600초 창이 끝나기 전이라도 가장 오래된 이름부터 제거됩니다. 같은 한도가 `"retained"`에도 적용됩니다. `strict` 필요 |
| `dispatchDeadline`이 없는 작업은 60초 후에 중단됩니다 | `functions.taskDispatchDeadlineSeconds` (`60`) | `600`: 녹화(recording)에서 Cloud Tasks가 이러한 작업에 부여한 값입니다. 15에서 1800 사이의 값을 설정할 수 있습니다. `strict` 필요 |
| 계속 실패하는 작업은 큐가 선언한 간격으로 재시도됩니다 | `functions.taskRetryBackoff` (`"declared"`) | `"production"`은 열두 번 실패한 뒤 간격이 선언된 최댓값을 넘어 늘어나도록 합니다(기록된 대로 4초, 8초, 10초). 선언된 값보다 빨라지는 일은 없습니다. `strict` 필요 |
| 재시도 값을 선언하지 않은 작업 큐 함수에 공식 에뮬레이터의 3회 시도가 적용됩니다 | `functions.taskRetryDefaults` (`"emulated"`) | `"production"`은 기본 큐를 읽어 온 값과 같이 100회 시도를 부여합니다(백오프 값은 동일). 선언한 값은 항상 유지됩니다. `strict` 필요 |
| ID 공급자 로그인이 내장, `oidc.*`, `saml.*` 공급자에 대해 픽스처 어설션과 로그인 위젯(`/emulator/auth/handler`)을 허용합니다. `strict`에서도 프로덕션과 같이 `oidc.*` 또는 `saml.*` 공급자는 구성되고 활성화되어 있어야 합니다(`auth.providers` 또는 Admin API) | `auth.idpAssertions` (`"fixture"`) | `"signed"`: OIDC ID 토큰은 `auth.idpSigners` 키로, SAML 응답은 공급자의 인증서로 검증되어야 하며, 픽스처와 내장 공급자는 거부됩니다 |
| Eventarc 리스너가 모든 자격 증명 또는 자격 증명 없음을 허용하므로 Admin SDK가 가짜 자격 증명으로 게시합니다([Eventarc 인증](https://github.com/fireemu/fireemu/blob/main/docs/eventarc-authentication.md) 참조) | `eventarc.authentication` (`"permissive"`) | `"production"`: 누락되었거나 형식이 잘못되었거나 JWT 형태인 베어러는 프로덕션의 401로 거부됩니다 |
| 테넌트 ID는 `tenant-a`처럼 읽기 쉬운 임의의 이름일 수 있습니다 | `auth.tenantIdFormat` (`"readable"`) | `"generated"`: `acme-x7k2q`와 같은 프로덕션의 생성 형식 |
| 멀티 테넌시가 켜져 있습니다. Admin API로 테넌트를 만들 수 있고 `updateConfig` 호출 없이 `auth.tenants`가 로드됩니다 | `auth.multiTenant.allowTenants` (`true`) | 새 프로덕션 프로젝트와 같이 활성화하기 전에는 설정되지 않습니다. 테넌트 라우트가 거부되고 `auth.tenants`에는 `allowTenants: true`가 필요합니다 |
| 다단계 인증(SMS와 TOTP)이 콘솔 토글, `updateConfig` 호출, `auth.mfa` 블록 없이 켜져 있습니다 | `auth.mfa` (`state: "ENABLED"`) | 새 프로덕션 프로젝트와 같이 활성화하기 전에는 꺼져 있습니다. 등록이 `OPERATION_NOT_ALLOWED : SMS based MFA not enabled.` 또는 `TOTP based MFA not enabled.`로 거부됩니다 |
| 최종 사용자의 Firestore `Listen` 스트림은 얼마나 오래 유지하든 열린 채로 있습니다. 제어 API의 `POST /v1/firestore/listen:expire`는 유지 중인 모든 최종 사용자 스트림을 프로덕션의 상태와 함께 한꺼번에 종료하여 클라이언트의 재연결을 테스트할 수 있게 합니다 | `firestore.listenStreamLifetime` (`"unlimited"`) | `"oneHour"`: 열린 지 한 시간 뒤 `INTERNAL`로 종료됩니다 |
| App Check가 앱 등록 없이 동작합니다. 형식이 올바른 디버그 토큰(UUIDv4)이면 어떤 앱에 대해서든 교환되므로, `appCheck` 블록 없이도 `enforceAppCheck` callable을 호출할 수 있습니다. 누락되었거나 형식이 잘못된 토큰은 여전히 거부됩니다 | `appCheck.debugTokens` (`"any"`) | `"registered"`: `appCheck.apps`의 앱 중 등록된 디버그 토큰 다이제스트가 있는 것만 교환되며, `appCheck` 블록이 없으면 App Check가 제공되지 않습니다. `appCheck` 블록이 있으면 이 역시 복원됩니다 |
| 선언되지 않은 Storage 버킷은 첫 쓰기 때 안내 메시지와 함께 생성됩니다 | `storage.undeclaredBuckets` (`"warn"`) | `"refuse"`: 객체 작업이 거부됩니다. 명시적인 키가 우선합니다 |
| 목록에 없는 Storage 버킷에 관대한 CORS 헤더가 붙습니다 | `storage.cors` | 목록에 없는 버킷에는 CORS 헤더가 없습니다. 명시적인 항목이 우선합니다 |
| 데드 레터 전달에 프로젝트 번호도 IAM 권한 부여도 필요하지 않습니다 | `pubsub.deadLetterAuthorization` (`"implicit"`) | `"iam"`: Pub/Sub 서비스 에이전트에 구독에 대한 `roles/pubsub.subscriber`와 데드 레터 토픽에 대한 `roles/pubsub.publisher`가 부여된 뒤에야 메시지가 전달됩니다. `pubsub.projectNumbers`를 지정해도 이 모드가 선택됩니다 |

시작 배너와 `fireemu capabilities`는 `productionExact`가 설정되었는지, 그리고 표에 있는 키 기반 개발용 기본값 각각의 유효한 값과 출처를 보고합니다. 목록에 없는 버킷의 CORS는 키 기반 개발용 기본값이 아닙니다.

대부분의 프로젝트에는 `productionExact`가 필요하지 않습니다. 프로덕션과 더 엄격하게 비교하기 위한 고급 스위치입니다.

복합 인덱스가 정의되지 않은 쿼리는 이 기본값에 포함되지 않습니다. `strict`는 프로덕션과 같이 이를 거부하며, `firestore.missingIndexes: "report"`는 쿼리를 실행하고 누락된 인덱스를 표준 오류로 보고하는 명시적인 옵트아웃입니다. `productionExact`는 이 키를 변경하지 않습니다.

### 그 밖의 개발 편의 기능

이러한 동작은 프로덕션과 다르며 `productionExact`로는 전환되지 않습니다. 각 행에 프로덕션의 동작을 얻는 방법, 또는 방법이 없다는 점이 적혀 있습니다.

#### 인증

| 개발용 동작 | 프로덕션의 동작을 얻는 방법 |
|---|---|
| `localhost`가 액션 링크 계속 URL의 기본 승인된 도메인에 포함되어 있습니다. 새 프로덕션 프로젝트에는 포함되어 있지 않을 수 있습니다 | `auth.authorizedDomains`를 선언합니다. 기본값을 대체합니다 |
| 이메일 링크 로그인을 포함해 모든 로그인 방법이 활성화된 상태로 시작합니다. 새 프로덕션 프로젝트에서는 아무것도 활성화되어 있지 않습니다(`firebase deploy --only auth`는 나열된 공급자만 켜고 끄지는 않습니다) | 프로젝트에 맞게 `auth.signIn`을 선언합니다. 예를 들어 이메일 링크 로그인을 거부하려면 `email.passwordRequired: true`를 지정합니다 |
| `google.com` 같은 내장 ID 공급자는 콘솔에서 활성화하지 않아도 로그인됩니다. `oidc.*`와 `saml.*` 공급자는 여전히 구성되고 활성화되어 있어야 하며, 그렇지 않으면 프로덕션처럼 로그인이 거부됩니다 | `auth.idpAssertions: "signed"`(`productionExact`가 설정함)는 내장 공급자를 거부합니다 |
| 프로젝트가 키를 선언하기 전에는 어떤 Web API 키든 허용됩니다. 프로덕션은 다른 프로젝트의 키에 `API_KEY_INVALID`로 응답합니다 | `auth.apiKeys`를 선언합니다 |
| 전화번호 인증은 reCAPTCHA, Play Integrity, APNs 증명 없이 어떤 번호로든 코드를 보냅니다. 프로덕션은 테스트 번호를 제외하고 이를 요구합니다 | 설정이 없습니다. 클라이언트 SDK는 검증기를 에뮬레이터 모드로 실행하므로 앱 경로는 검증되지만, 증명을 생략하는 원시 REST 클라이언트는 여기서 통과합니다 |
| reCAPTCHA `ENFORCE` 상태는 저장되고 반환되지만 강제되지 않으므로 reCAPTCHA 토큰이 없는 로그인도 허용됩니다 | 설정이 없습니다 |
| `accounts:batchCreate`에는 행 수 제한이 없습니다. Admin SDK는 전송하기 전에 호출당 1000명의 사용자를 확인합니다 | 설정이 없습니다 |
| 가입 속도 제한(프로덕션은 IP별로 신규 계정을 제한합니다)은 시뮬레이션되지 않습니다 | `auth.quotaSimulation.mode`를 `"enforce"`로 설정합니다 |
| 함수 안에서 Admin SDK의 `verifyIdToken`은 서명되지 않은 ID 토큰을 허용합니다. `FIREBASE_AUTH_EMULATOR_HOST`가 설정되어 있으면 SDK가 서명 검증을 건너뛰기 때문이며, 프로덕션은 이를 거부합니다 | 설정이 없습니다. [Auth](../../products/auth/#토큰)를 참조하십시오 |

#### Cloud Firestore

| 개발용 동작 | 프로덕션의 동작을 얻는 방법 |
|---|---|
| Firestore는 데몬의 프로젝트가 아닌 다른 프로젝트를 지정한 요청을 해당 프로젝트의 비어 있는 자체 데이터로 처리하므로 병렬 테스트가 서로 분리됩니다. `projectId`의 오타는 프로덕션의 `PERMISSION_DENIED`처럼 실패하지 않고 데이터를 분리합니다 | `projects.unknownProjects`를 `"refuse"`로 설정합니다 |
| `firestore.indexes.json`의 복합 인덱스는 즉시 `READY`가 되고, Admin API로 만든 인덱스는 약 1.5초 뒤에 `READY`가 됩니다. 프로덕션은 인덱스를 만드는 데 몇 분이 걸립니다. `CREATING` 상태와, 해당 인덱스가 필요한 쿼리에 대한 "currently building" 거부는 유지됩니다 | 설정이 없습니다. 프로덕션을 대상으로 할 때와 같이 인덱스가 `READY`가 될 때까지 폴링합니다. 가상 시계를 앞으로 돌려도 빌드가 완료됩니다 |
| 관리형 내보내기, 가져오기, 대량 삭제 작업은 첫 번째 폴링에서 완료됩니다. 프로덕션에서는 몇 분이 걸립니다 | 설정이 없습니다. 프로덕션을 대상으로 할 때와 같이 작업이 `done`이 될 때까지 폴링합니다 |
| 다른 작성자가 기다리는 잠금을 쥐고 있는 트랜잭션은 활동 없이 60초(실제 시계 기준)가 지나면 롤백됩니다. 프로덕션 자체의 유휴 제한은 약 110~123초이며, 그보다 이른 시점에 경합 중인 보유자에게 어떤 일이 일어나는지는 기록되어 있지 않습니다 | 설정이 없습니다 |

#### Cloud Storage

| 개발용 동작 | 프로덕션의 동작을 얻는 방법 |
|---|---|
| 서명된 URL이나 POST 정책은 어떤 서명이든 허용됩니다(만료와 조건은 확인합니다). 서명을 검증하려면 서명 서비스 계정의 키가 필요하기 때문입니다 | V4 서명된 URL의 경우 서명에 사용한 키를 `storage.signedUrlKeys`에 등록합니다. POST 정책 서명은 검증되지 않습니다 |
| JSON API는 자격 증명이 없는 요청, 또는 Firebase ID 토큰이 아닌 다른 자격 증명이 있는 요청을 소유자로 처리합니다. 로컬 실행에서는 액세스 토큰을 판단할 수 없기 때문입니다 | 사용할 수 없습니다 |
| 버킷 수준의 공개 권한 부여(IAM `allUsers`)는 API로 설정할 수 없습니다 | 버킷을 `storage.publicBuckets`에 나열합니다 |
| 공개 URL(`GET /{bucket}/{object}`)은 `x-goog-api-client`를 보내는 요청에 대해 자격 증명 없이 제공됩니다. Go 클라이언트 라이브러리(및 Firebase Admin Go SDK)가 에뮬레이터 호스트에 대해 자격 증명 없이 이 경로로 읽기 때문입니다. 브라우저 fetch는 거부됩니다 | 사용할 수 없습니다 |
| Security Rule이 Storage 서비스 에이전트에 대해 프로덕션에서 필요한 Firestore 접근 권한 부여 없이도 `firestore.get()`과 `firestore.exists()`를 호출할 수 있습니다 | 사용할 수 없습니다 |
| 프로덕션 프로젝트에는 둘 중 하나만 있지만, 기본 버킷 이름 `<project>.appspot.com`과 `<project>.firebasestorage.app`이 둘 다 존재합니다 | `storage.defaultBucket`을 프로젝트에 있는 이름으로 설정합니다. 다른 이름은 선언되지 않은 상태이며 해당 버킷이 생길 때까지 버킷 리소스는 404로 응답합니다. `storage.undeclaredBuckets`는 첫 쓰기가 이를 안내 메시지와 함께 생성할지(`"warn"`), 조용히 생성할지(`"create"`), 거부할지(`"refuse"`, 재정의하지 않으면 `productionExact`가 선택)를 제어합니다 |

#### Cloud Functions

| 개발용 동작 | 프로덕션의 동작을 얻는 방법 |
|---|---|
| Functions 코드베이스의 `.env.local`이 `.env`와 `.env.<projectId>` 뒤에 적용됩니다. 프로덕션은 이 파일을 배포하지 않습니다 | 대신 값을 `.env` 또는 `.env.<projectId>`에 넣습니다. `.env.local`에만 있는 키는 프로덕션에서 설정되지 않습니다 |
| `retry`가 활성화된 상태에서 실패한 함수는 총 4회 재시도되고(`events.maxAttempts`, 가상 시계 기준 10초에서 600초 백오프) 이후 데드 레터로 보내집니다. 프로덕션은 최대 24시간(2세대) 또는 7일(1세대) 동안 재시도합니다 | `events.maxAttempts`를 늘립니다. 시간 창을 그대로 재현하는 값은 없습니다 |
| 공개되지 않은 함수(`invoker: "private"` 또는 서비스 계정 목록)와 작업 큐 함수는 공개 함수 URL에서 Google이 발급한 ID 토큰처럼 보이는 모든 베어러(`iss`가 `https://accounts.google.com`인 JWT)를 허용합니다. Google이 수행하는 서명과 IAM 역할의 검증을 로컬에서는 실행할 수 없기 때문입니다. Firebase Auth ID 토큰은 Cloud Run이 거부하는 것과 같이 401로 거부됩니다. 자격 증명이 없는 호출은 프로덕션과 같이 403으로 거부됩니다. 콘솔과 제어 API는 제어 토큰으로 이러한 함수를 호출합니다 | 방법이 없습니다. 자격 증명 없이 호출을 보내 거부되는 것을 확인하십시오. `ingressSettings`는 적용되지 않습니다 |

#### Pub/Sub

| 개발용 동작 | 프로덕션의 동작을 얻는 방법 |
|---|---|
| Pub/Sub는 자격 증명 없는 요청을 허용하므로 `PUBSUB_EMULATOR_HOST`를 사용하는 클라이언트가 동작합니다 | `pubsub.authentication.localBearerToken`을 설정합니다. 이후 자격 증명 없는 요청은 프로덕션과 같이 거부됩니다. [Pub/Sub와 Eventarc](../../products/pubsub-eventarc/#인증)를 참조하십시오. |
| Pub/Sub 푸시 엔드포인트는 루프백(`127.0.0.1`, `localhost`, `[::1]`)의 일반 `http://`일 수 있습니다. 프로덕션은 HTTPS를 요구합니다 | 구독에 루프백이 아닌 `https://` URL을 사용합니다. Fireemu는 푸시 메시지를 루프백으로만 전달하므로, 루프백이 아닌 곳에 도달하게 하는 설정은 없습니다 |
