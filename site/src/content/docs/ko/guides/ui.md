`fireemu up`은 `http://127.0.0.1:4000/ui/`에서 Emulator UI를 제공합니다. 데이터를 탐색하고 변경하고, 함수를 실행하고, Security Rules 결정을 읽고, 시계를 이동하는 데 사용합니다.

## UI 열기

```sh
# Another port
npx fireemu up --ui-port 4001

# No UI
npx fireemu up --ui-port 0

# exec starts no UI unless asked
npx fireemu exec --ui -- npm test
```

기본 포트가 사용 중이면 `up`은 UI 없이 시작되므로 시작 출력을 확인하십시오.

## 표시되는 내용

| 페이지 | 할 수 있는 작업 |
| --- | --- |
| **Overview** | 프로젝트, 버전, 가상 시계(멈춤 또는 실제 시간을 따름), 실행 중인 서비스, 그리고 에뮬레이터가 응답하는 `Host` 이름(기본 제공 이름, `network.allowedHosts`로 추가한 항목, 단일 레이블 이름의 허용 여부)을 확인합니다. |
| **Authentication, Firestore, Storage** | 사용자, 문서, 객체를 탐색하고 관리합니다. |
| **Functions** | 등록된 함수와 각 함수의 런타임(Node.js 또는 Python, 그리고 `firebase.json`이 선언한 `runtime`), 트리거, 호출 결과와 로그, 런타임 상태를 확인합니다. 런타임 상태에는 대기 중, 실행 중, 재시도 대기 중 또는 데드 레터 처리된 작업, 이벤트 큐가 가득 차 있는 동안 보류된 Auth 이벤트, 진행 중인 작업, 각 코드베이스 러너의 상태, 러너가 찾았지만 서비스할 수 없었던 export가 포함됩니다. 예약 함수를 즉시 실행하거나 시계를 다음 발생 시점까지 앞당길 수 있습니다. |
| **Hosting** | Fireemu가 제공하는 사이트, 로컬 URL, 공개 디렉터리(시작 시 존재하지 않았다면 경고와 함께), 그리고 적용 순서대로 정렬된 리라이트, 리디렉션, 헤더를 확인합니다. 이 페이지는 `firebase.json`을 읽으며 요청을 기록하지 않습니다. |
| **Realtime Database** | 경로의 데이터를 탐색하고, 로컬 관리자로서 교체, 패치, 삭제하고, 인스턴스의 Rules를 읽고 교체하며, 익명 요청을 실행해 Rules가 어떻게 응답하는지 확인합니다. |
| **Alerts** | Firebase 알림을 이를 수신하는 함수에 게시합니다. |
| **Rules** | 추적된 최신 Firestore Security Rules 결정 100개를 제한된 표현식 결과와 함께 읽습니다. 추적은 UI 또는 첫 제어 API 읽기와 함께 시작되며, 새 규칙 집합은 이력을 지웁니다. 진단 한계는 [Security Rules](../security-rules/)를 참조하십시오. |
| **App Check** | 등록된 앱과 디버그 토큰을 확인합니다. |
| **Runtime** | 가상 시계를 앞으로 이동하거나, **Allow moving backwards**로 뒤로 이동하고, 장애 계획(아래 참조)을 설치합니다. |

## 장애 계획 설치

Runtime 페이지의 **Fault plan** 아래에서 다음을 수행합니다.

1. Functions 이벤트 재시도, 중복 전달, 시도 지연 또는 타임아웃, 처음 몇 번의 시도 실패 중 하나에 해당하는 레시피를 선택하고 매개변수를 입력합니다.
2. **Fill plan**을 선택합니다. 계획이 JSON 편집기에 채워지며, 설치되지는 않습니다.
3. JSON을 검토하거나 편집한 다음 **Install**을 선택해 선택한 세션에 적용합니다.

파싱 가능한 계획에는 테스트에서 같은 계획을 설치할 수 있는, 복사 가능한 `fireemu/testing` 및 제어 API 스니펫도 제공됩니다. **Clear**는 설치된 계획을 제거합니다.

## 데이터베이스 선택과 쿼리 재현

### Firestore 데이터베이스 선택

Firestore 데이터베이스 필드에는 현재 프로젝트의 알려진 데이터베이스와 최근에 연 이름이 표시됩니다. 이름을 직접 입력한 뒤 **Open database**를 선택할 수도 있습니다.

- 선택이 바뀔 때마다 카탈로그를 다시 확인하며, **Refresh**는 선택을 바꾸지 않고 카탈로그를 확인합니다.
- 카탈로그 요청의 실패는, 성공한 카탈로그 응답에 데이터베이스가 없는 경우와 별도로 보고됩니다.
- 최근 이름은 선택한 세션과 프로젝트로 범위가 한정되며 브라우저 탭의 세션 스토리지에만 보관됩니다.

### Node.js SDK로 쿼리 재현

쿼리 패널의 **Node.js SDK reproduction** 섹션은 저수준 Firestore Node.js SDK를 사용하는 스크립트를 생성합니다. 이를 통해 64비트 정수와 타임스탬프 나노초를 포함한 형식 있는 쿼리 값이 보존됩니다.

스크립트에 나열된 패키지를 설치하고 `query.cjs`로 저장한 다음, 실행하기 전에 `FIRESTORE_EMULATOR_HOST`를 로컬 Firestore 포트로 설정하십시오. 스크립트는 루프백이 아닌 엔드포인트를 거부합니다. 콘솔 쿼리와 마찬가지로 클라이언트 Security Rules를 테스트하지 않고 로컬 관리자 접근을 사용합니다.

쿼리 초안은 데이터베이스별로 유지됩니다. Firestore 뷰는 변경된 경로를 기준으로 영향받은 문서를 새로 고치며, 행에 사용할 수 있는 업데이트 시각이 없으면 멤버십 새로 고침을 수행합니다.

## 연결 확인과 공유 가능한 Functions 필터

### 연결 배지

헤더의 연결 배지는 모든 제품 리스너의 상태가 아니라 제어 API의 응답을 나타냅니다.

- 마지막으로 성공한 확인은 에뮬레이터의 가상 시계와 무관하게 실제 시각(wall-clock)을 사용합니다.
- 확인이 실패하면 이전에 성공한 타임스탬프가 유지되며, 선택한 세션을 바꾸면 해당 대상이 응답할 때까지 지워집니다.
- 연결 변경은 보조 기술에 알려집니다.

### Functions 필터 링크

Functions의 함수 이름 및 로그 수준 필터는 URL에 유지됩니다. 검색 텍스트는 선택한 세션과 프로젝트로 범위가 한정되어 탭의 세션 스토리지에 남으며, **Include search text in the shared link**를 명시적으로 선택하고 **Copy filter link**를 사용하는 경우에만 링크에 포함됩니다. 공유하기 전에 검색 텍스트를 검토하십시오.

- 링크에는 필터 설정이 들어 있을 뿐 로그 레코드의 저장된 사본이 들어 있지 않습니다. 다른 사용자가 링크를 열 때는 레코드가 더 이상 보존되지 않을 수 있습니다.
- 브라우저 스토리지를 사용할 수 없으면 비공개 텍스트는 페이지가 마운트된 동안에만 유지됩니다.
- 이벤트 링크는 해당 세션을 선택하며, 브라우저의 뒤로 가기나 앞으로 가기로 다시 방문한 경우도 마찬가지입니다. 이벤트가 더 이상 보존되지 않으면 페이지가 만료되었다고 알려 줍니다.

### 클립보드

클립보드 접근이 실패하면, Overview 페이지는 성공했다고 보고하는 대신 키보드로 직접 복사할 수 있는 포커스된 읽기 전용 텍스트 필드를 제공합니다.
