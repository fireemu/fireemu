FireemuはFirebase Realtime Databaseを`127.0.0.1:9000`で提供します。REST API、SDKが使うリアルタイムプロトコル、Security Rules、Firebase CLI形式のエクスポートとインポートに対応しています。記録されたケースについては本番と照合して検証されていますが、より広範な本番との互換性は未検証のままです（[本番との違い](#本番との違い)を参照）。

公式エミュレータ（firebase-tools 15.28.2が実行するfirebase-database-emulator v4.11.2）とも比較していますが、これに対する一致の主張はまだありません。そのため、[互換性コントラクト](../../compatibility/)ではこの比較を未解決のギャップとして挙げています。本番が観測されていない箇所で公式エミュレータからそのまま取り入れた挙動は、変更される可能性があります（[暫定的な挙動](#暫定的な挙動)を参照）。

## 接続

### データベースを起動する

データベースは、選択または設定されたときに起動します。次のいずれもなければ、デフォルトの実行ではポート9000は使用されません。

- `--only database`（他のサービスと併用する場合: `--only auth,firestore,database`）。
- `firebase.json`の`emulators.database`（`firebase init`が書き出す形式）。
- `fireemu.toml`の`daemon.databasePort`、または`--database-port`。

```sh
npx fireemu exec --only database -- npm test
```

```json
{
  "emulators": { "database": { "port": 9000 } }
}
```

ポートが使用中の場合、起動は止まります（`error: bind 127.0.0.1:9000: Address already in use`）。9000はPHP-FPMのデフォルトでもあるため、`--database-port`または`emulators.database.port`で別のポートを選ぶか、`--only`でデータベースを除外してください。

起動時のバナーには、アドレスと有効なルールが表示されます。

```text
  database:         127.0.0.1:9000   FIREBASE_DATABASE_EMULATOR_HOST=127.0.0.1:9000
  database rules:   demo-app-default-rtdb <- ./database.rules.json; another instance: every request is allowed (database.defaultAccess = open, default)
```

### SDKを向ける

`fireemu exec`は、実行するコマンドに対して`FIREBASE_DATABASE_EMULATOR_HOST`を設定し、Admin SDKがそれを読み取ります（[環境変数](../../reference/environment-variables/)を参照）。

`exec`は、firebase-toolsと同様に、`databaseURL`を`https://<project>.firebaseio.com`とした`FIREBASE_CONFIG`も設定します。そのため、オプションなしで初期化されたAdmin SDKアプリは、`<project>-default-rtdb`ではなくインスタンス`<project>`を読み書きします。`<project>-default-rtdb`は、単一形式のルールと、下のクライアントの例が使うものです。クライアントとインスタンスを共有するには、`initializeApp`に`databaseURL: 'https://<project>-default-rtdb.firebaseio.com'`を渡してください。

Webとモバイルのクライアントは、明示的に接続します。

```js
import { initializeApp } from 'firebase/app';
import { getDatabase, connectDatabaseEmulator } from 'firebase/database';

const app = initializeApp({ projectId: 'demo-app', databaseURL: 'https://demo-app-default-rtdb.firebaseio.com' });
const db = getDatabase(app);
connectDatabaseEmulator(db, '127.0.0.1', 9000);
```

### インスタンス

データベースインスタンスは名前空間です。リクエストは、公式エミュレータと同様に、`ns`クエリパラメータまたはホスト名の最初のラベルでインスタンスを選択します。`demo-app-default-rtdb`は、プロジェクト`demo-app`のデフォルトインスタンスです。IDトークンは、そのインスタンスについてはそのプロジェクトに対して、それ以外の名前のインスタンスについてはデーモンのプロジェクトに対して検証されます。セッションのリセットとセッションスナップショットは、`<project>`と`<project>-default-rtdb`を対象とします。

## 提供される機能

- REST API（`.json`パス）: 読み取り、書き込み、更新、プッシュID、ETagによる条件付きリクエスト、`shallow`、`print`、`format=export`、クエリ、イベントストリーム（`Accept: text/event-stream`）。
- WebSocketとロングポーリング（`forceLongPolling()`）上のリアルタイムプロトコル。リッスン、クエリ、トランザクション、サーバー値に対応します。
- `onDisconnect`の書き込み（`set`、`update`、`remove`、`cancel`）。接続が終了したときに、どのような終わり方でも、そのときに解決されたサーバー値を持つ1回の更新として実行されます。Fireemu自体が停止するときには、公式エミュレータが停止時にこれらを実行しないのと同様に、実行されません。セッションのリセットは、リセット対象のプロジェクトに登録されたものを破棄します。
- [Security Rules](#security-rules)、`/.settings/rules.json`、`/.inspect/databases.json`、書き込みでの`disableTriggers`。
- [エクスポート、インポート、セッションスナップショット](#エクスポートインポートスナップショット)。

リポジトリの`tools/sdk-smoke-database`は、固定されたバージョンの`firebase`と`firebase-admin`のSDKを通じてこれらを実行し、結果を公式エミュレータの記録と比較します。

### RESTのオプション

- 通常のREST読み取りは、`timeout`を15分以下の正の期間（たとえば`1s`、`2seconds`、`3min`）として検証します。これはオプションを検証するだけで、リクエストのデッドラインは設定しません。書き込み、shallow読み取り、条件付き読み取りでは無視されます。無効な期間は拒否されます。期間のオーバーフローは500を返すことがあります。
- `shallow=true`は`limitToFirst`とプレーンテキストの`startAfter`を受け付け、`limitToLast`、`startAt`、`endAt`、`orderBy`を拒否します。
- 読み取りは`writeSizeLimit`を無視し、書き込みは`format`を無視します。
- 条件付きレスポンスはETagを保持します。`if-none-match`のPUTは`print=silent`でもETagを含み、`X-Firebase-ETag: true`は、304、拒否された条件付きPUT（412）、POSTでもETagを要求します。
- `strict`では、パス内の不正なパーセントエスケープは`application/octet-stream`と`Bad request.`の400を返します。`emulator`プロファイルは公式エミュレータの応答を維持します。

### マルチパス書き込みの順序

1回のマルチパス書き込み（RESTの`PATCH`、SDKの`update()`、終了する接続の`onDisconnect`の書き込み）のエントリは、公式エミュレータの順序で接続のリッスンに届きます。4件までは送信または登録された順序、5件以上はキーのハッシュの順序です。書き込まれた場所以上の位置にあるリッスンが最初に受け取ります。本番の記録1件が6個のキーの集合で一致しています。それ以外の形式は公式エミュレータに従っており、本番では観測されていません。

## Security Rules

ルールは`.read`、`.write`、`.validate`、`.indexOn`に対応し、REST、イベントストリーム、リアルタイムプロトコルにわたって、`auth`、`now`、`root`、`data`、`newData`、`query`、`$`の各変数を使えます。

### ルールを読み込む

Firebase CLIと同様に、`firebase.json`でルールファイルを指定します。単一形式は、1つのファイルをデフォルトインスタンスの`<project>-default-rtdb`に読み込みます。

```json
{
  "database": { "rules": "database.rules.json" }
}
```

配列形式は、各エントリを、その`instance`に、または`.firebaserc`のデプロイ`target`のインスタンスに読み込みます。

```json
{
  "database": [
    { "instance": "demo-app-default-rtdb", "rules": "database.rules.json" },
    { "target": "audit", "rules": "audit.rules.json" }
  ]
}
```

読み込めないルールファイルがあると、firebase-toolsが停止するのと同様に、ファイル、行、列とともに起動が止まります。Fireemuの実行中にファイルが変更された場合は、再度読み込まれます。読み込めない変更があった場合は、有効なルールを維持し、その理由を出力します。

`GET`と`PUT /.settings/rules.json?ns=<instance>`は、管理者の認証情報でインスタンスのルールを読み取り、置き換えます。`@firebase/rules-unit-testing`がルールを読み込む方法でもあります。このルートは、FirestoreとStorageのルールのルートと同様に、ループバックのピアを必要とします。ループバック以外のピアには、認証情報が評価される前に403が返されます。先頭のスラッシュの繰り返しやパーセントエンコードされた`.settings`パスにも、同じ制限が適用されます。

### ルールファイルのエラー

無効なルールの読み込みでは、最初の構文エラー、キーの重複、または無効なインデックス名のエラーを報告します。構文解析できるドキュメントでは、型エラーと名前のエラーが、ルールの順序で報告されます。順序は`.read`、`.write`、`.validate`、続いてファイル順の名前付きの子、最後にワイルドカードの子で、収集には上限があります。サポートされないJavaScriptの構文要素は引き続き失敗します。より多くの形式を解析できるようにしても、エラーメッセージが改善されるだけで、それらが有効になるわけではありません。記録されたケースは、あらゆる不正な入力を網羅しているわけではありません。

### 比較したもの

公式エミュレータとの比較は、RESTの読み取りと書き込み、範囲/件数クエリの有無それぞれのイベントストリーム、クエリなし（`q`が存在しない、または空）のリアルタイムのリッスンをカバーします。クエリ付きのWebSocketのリッスンのあらゆる形式を確認したわけではありません。ロングポーリングは、共有されたリアルタイムセッションの挙動を使用します。

記録された有限の本番のREST Rules、クエリに依存するルール、クエリ境界のケースは、記録されたロングポーリングのトランザクションフレームとともに、どちらのプロファイルでも再生されます。これらの観測がカバーするのは記録されたリクエストであり、あらゆるルール、クエリ、トランザクションの形式での一致を確立するものではありません。

### イベントストリームとリッスン

クエリが範囲や件数を制限するイベントストリームは、そのクエリで判定されます。クエリが並べ替えるだけのものは、すべてのデータを読み取り、公式エミュレータと同様に、クエリなしのストリームとして判定されるため、インデックスは不要です。

ルールの変更、データに依存する`.read`が許可するものを変更する書き込み、またはクライアントのサインインやサインアウトにより、ルールがもはや許可しなくなったリッスンとイベントストリームはキャンセルされます。

### `onDisconnect`の書き込みとルール

`onDisconnect`の書き込みは、登録時と接続の終了時の両方でチェックされます。

- **登録時。** `set`は1回の書き込みとして、`update`はエントリごとに、それぞれ現在のツリーに対してチェックされます。いずれかのエントリが失敗すると、登録は拒否されます。
- **切断時。** 保留中の各エントリは、最初にその時点のツリーに対して単独でチェックされます。`.write`または`.validate`で拒否されたエントリは破棄されます。その後、残ったエントリがまとめて1回の更新としてチェックされます。その組み合わせのチェックが失敗した場合、どれも適用されません。

記録された本番のケースでは、数値の優先度で登録されたonDisconnectの値の子をキャンセルすると、無関係な書き込みを含め、その接続の更新全体が破棄されます。記録された2ラウンドは、子のキャンセル後の再登録、ネストした優先度、文字列の優先度もカバーします。それぞれの形式の記録された2ラウンドが、各プロファイルで再生されました。それ以外の優先度とキャンセルの形式は、本番では未検証のままです。

### 認証情報

| 認証情報 | `emulator`プロファイル | `strict`プロファイル（デフォルト） |
|---|---|---|
| `Authorization: Bearer owner`または`access_token=owner`（エミュレータのオーナー認証情報） | 管理者。ルールは適用されません | 管理者。ルールは適用されません |
| それ以外の単一の`Authorization: Bearer`または`access_token` | 公式エミュレータと同様に管理者。`network.allowNonLoopbackHosts`で公開しない限り、リスナーはループバックにあります。まず[CIとコンテナ](../../guides/ci-and-containers/)を参照してください | 401で拒否されます。イベントストリームではないデータパスの読み取りについては、測定時に本番が応答した内容と同じく、本文は`Unauthorized request.`です（空のBearerは`Permission denied`のままです） |
| FireemuのAuthが署名した`auth=<ID token>` | トークンが指すユーザー。カスタムクレームは`auth`のメンバーになります | トークンがそのインスタンスのプロジェクト向けである場合、トークンが指すユーザー |
| `auth=<unsigned ID token>`（`@firebase/rules-unit-testing`、`mockUserToken`） | `auth.allowUnsignedIdTokens`が`true`（デフォルト。`productionExact`では`false`で、その場合は匿名になります）の間、公式エミュレータの読み取りどおりに、どのプロジェクトを指していても、`aud`の有無にかかわらず、その`sub`が指すユーザー | `auth.allowUnsignedIdTokens`が`true`（デフォルト。`productionExact`では`false`）の間、`createMockUserToken`の形式で、そのインスタンスのプロジェクトをaudienceとしている場合に、トークンが指すユーザー |
| Fireemuが検証できない、RS256またはHS256で署名された`auth=<token>` | 署名なしトークンが受け付けられ、FireemuのAuthが独自のトークンに署名しない間、トークンが空でない署名、そのインスタンスのプロジェクトを`aud`、将来の`exp`、存在するテナント（指定している場合）を持つとき、公式エミュレータの読み取りどおりに、そのクレームが指すユーザー。それ以外は匿名 | 401で拒否されます |
| それ以外の`auth=`の値 | 匿名 | 401で拒否されます。ただし、イベントストリームではないデータパスの読み取りで、不透明な値（英字と数字の1文字から128文字、`null`や`owner`ではないもの。クエリのデコード後に判定）の場合は、測定時に本番が応答した内容と同じく未認証として扱われます。つまり、ルールが全員に開放しているパスは読み取られ、保護されたパスは拒否されたままです |

この表を適用する前に、Fireemuは、どちらのプロファイルでも、曖昧なHTTPリクエストを400で拒否します。繰り返されたクエリパラメータ（`auth`と`access_token`を含む）、複数の`Authorization`ヘッダー、またはクエリの認証情報と`Authorization`ヘッダーの組み合わせが該当します。同一の認証情報の繰り返しも曖昧です。公式エミュレータは代わりに1つの値を選択するため、これは一覧に挙げた違いです。

`auth_variable_override`（Admin SDKが`databaseAuthVariableOverride`のために送信するもの）も持つ管理者のRESTリクエストは、記録されたケースで本番が評価したとおりに、ルールによってその`auth`の値として評価されます。`null`は未認証として読み取られ、不正なオーバーライド、またはオブジェクトでも`null`でもないオーバーライドは拒否されます。

`firebase emulators:export`が読み取る`/.inspect/databases.json`は、`emulator`プロファイルでは誰にでも応答し、`strict`またはデータベースがロックされている場合は`owner`認証情報にのみ応答します。

### ルールのないインスタンス

ルールファイルのないインスタンスは、`database.defaultAccess`に従います。

- `"open"`（どちらのプロファイルでも開発時のデフォルト）: 公式エミュレータがルールのないデータベースを提供するのと同様に、すべてのリクエストが許可されます。
- `"locked"`（`productionExact`のデフォルト。`strict`プロファイルのみ）: ロックモードの新しい本番データベースが管理者のみを許可するのと同様に、`owner`認証情報だけが読み書きできます。サインイン済みのユーザーを含め、それ以外のすべての認証情報は401で拒否されます。

### `@firebase/rules-unit-testing`によるユニットテスト

`initializeTestEnvironment`は、渡されたルールを`/.settings/rules.json`経由で読み込み、`authenticatedContext()`は署名なしのモックトークンを送信し、`withSecurityRulesDisabled()`と`clearDatabase()`にも対応しています。

```js
import { initializeTestEnvironment, assertFails, assertSucceeds } from '@firebase/rules-unit-testing';
import { readFileSync } from 'node:fs';

const [host, port] = process.env.FIREBASE_DATABASE_EMULATOR_HOST.split(':');
const testEnv = await initializeTestEnvironment({
  projectId: 'demo-app',
  database: { host, port: Number(port), rules: readFileSync('database.rules.json', 'utf8') },
});
const alice = testEnv.authenticatedContext('alice').database();
await assertSucceeds(alice.ref('users/alice').set({ name: 'Alice' }));
await assertFails(alice.ref('users/bob').set({ name: 'Mallory' }));
await testEnv.cleanup();
```

`npx fireemu exec --only database -- node test.mjs`で実行します。

署名なしトークンに対する本番の拒否をテストするには、`auth.allowUnsignedIdTokens`を`false`に設定するか、[`productionExact`](../../guides/profiles/)を設定します。すると、リアルタイム接続はモックトークンを拒否し（`invalid_token`）、SDKは再試行を続けるため、`authenticatedContext()`からの読み取りや書き込みは失敗せずに、完了しないままになります。拒否はRESTで確認する（`?auth=<token>`は401で応答します）か、アサーションにタイムアウトを設定してください。

### ルールのカバレッジ

`/.inspect/coverage?ns=<instance>`（HTMLビューア）と`/.inspect/coverage.json?ns=<instance>`は、公式エミュレータと同様に、読み込まれたルールの各式について、それが生成した結果を報告します。

- 収集は常にオンで、記録される結果ごとにハッシュの参照が1回だけかかります。
- 長時間の実行を高速かつ小さく保つため、各式は最初の64個の異なる結果（および文字列値は最大64 KiB）を保持し、それ以降の新しい結果は一覧に載せず`values-omitted`に数えられます。
- `data`や`root`のようなスナップショットの値は、評価のたびに新しいアイデンティティになるため、一覧はすぐにいっぱいになります。
- 変更されたルールを読み込むと新しいレポートが始まります。同じテキストを再度読み込んだ場合は、レポートが維持されます。

## エクスポート、インポート、スナップショット

`emulators:export`、`--export-on-exit`、Hubのエクスポートは、データを保持している、またはインポートされたすべてのインスタンスについて`database_export/<instance>.json`を書き出します。形式は`GET /.json?format=export`のエクスポート形式（優先度を保持）で、firebase-toolsが書き出す`firebase-export-metadata.json`の`database`セクションが付きます。ファイルは、同じデータであればFirebase CLIのものとバイト単位で同一であり、各ツールは相手のエクスポートをインポートできます。

```sh
npx fireemu exec --only database --export-on-exit ./emulator-data -- npm test
npx fireemu exec --only database --import ./emulator-data -- npm test
```

`--import`は、firebase-toolsと同様に、コマンドの開始前に、各ファイルを`owner`認証情報と`disableTriggers=true`で書き込みます。

- 小文字化したファイル名がインスタンスになります。
- 無効なインスタンス名のファイル、またはデータベースが拒否するファイル（無効なJSON、無効なキー、深すぎるネストしたデータ）があると、他のプロダクトのデータがインストールされる前に起動が止まります。
- データベースが選択されていない場合、エクスポートのデータベースセクションは、注記とともにスキップされます。

セッションスナップショットとリセットには、そのセッションのプロジェクトのインスタンスが含まれます。リストアまたはリセットは、開いているリスナーとイベントストリームから観測され、復元されたデータに対してルールがもはや許可しなくなったものはキャンセルされ、それらのインスタンスに登録された`onDisconnect`の書き込みは破棄されます。

[テストワールド](https://github.com/fireemu/fireemu/blob/main/docs/test-worlds.md)では、`services`で`database`を選択します。`world.endpoints.database`と`FIREBASE_DATABASE_EMULATOR_HOST`がそこにルーティングされ、そのデータはエクスポート、インポート、リセットを通じて維持されます。

## ローカルのFunctionsトリガー

ローカルのv1とv2のデータベースハンドラーは、プロジェクト、インスタンス、リファレンスパターンの範囲に限定されたcreate、update、delete、writeのイベントを受け取ります。ランナーがFirebase SDKのスナップショットオブジェクトを提供します。

- 変更のない書き込みは、変更イベントを発行しません。
- ソースの変更と、それに予約されたイベントバッチは、一緒にコミットされます。
- どのトリガーのリファレンスにも到達しない書き込みは、スナップショットを取得せずに適用されるため、あるパスのトリガーが他の場所の書き込みにコストを加えることはありません。
- セッションのリセットは、ソースデータをクリアしてFunctionsのエポックを退役させる間、並行するデータベースの変更を排除します。

### イベントキューがいっぱいのとき

- ローカルのイベントキューがいっぱいの間、イベントが空のキューに収まる書き込みは503で拒否され、配信が進んでからの再試行で成功します。
- イベントが決して収まらない書き込み（たとえば、`/users/{uid}`のトリガーの下に5,000個の子を1回の`PUT`で書き込むなど、4096件を超えるイベント、またはシリアライズ後64 MiBを超えるイベント）は、本番での適用と同様に、キューの状態にかかわらず、イベントなしで適用されます。

### イベントサイズ

- **`emulator`プロファイル。** 呼び出しフレーム（16 MiB）より大きいイベントは単独で破棄され、その書き込みの他のイベントは配信されます。最初の破棄で警告が出力され、それぞれがリソース診断で`admission.database_fanout_dropped`として数えられます。
- **`strict`プロファイル。** 登録済みのトリガーのリファレンスに到達する書き込みで、そのイベント（書き込み前のノードにデルタを加えたもの。コンパクトなJSON）が1,048,576バイト（1 MiB）より大きい場合は、`400`と`This request would cause a function payload exceeding the maximum size allowed.`で拒否され、何も適用されません。本番が2 MiBの値に対して行ったのと同じです。SDK接続には、同じテキストで`invalid_parameters`が返されますが、この形式は記録されていません。

strictのしきい値は、2026-11-08と2026-11-09の記録に由来します。1,023,9xxバイトのイベントは受け付けられて配信され、1,049,9xxバイトのイベントは拒否されました。本番はイベントあたり1 MBと文書化しているため、1 MiBを使用しています。これら2つのサイズの間の正確なしきい値と、イベントの数え方は検証されていません。

### 優先度

strictのイベントは、本番のイベントと同様に優先度を持ちません。書き込み前のノードには優先度がなく、作成されたノードのデルタはそのプレーンな値であり、優先度のみの書き込みはデルタ`{".priority": n}`を送ります。emulatorプロファイルは、従来から送っていたイベントを維持します。

### リージョン

ローカルのインスタンスは`us-central1`にあります。別のリージョンの第2世代トリガーは発火せず、公式エミュレータが警告するのと同様に、読み込み時に警告が出ます。本番では、自身のリージョンのインスタンスに対してのみ発火します。

### イベントメタデータと記録されたもの

本番の観測は、v1とv2のハンドラーに対する、管理者と未認証の書き込みの固定された一連の流れをカバーします。それらの記録された配信については、strictプロファイルは、観測されたイベントID、ミリ秒のタイムスタンプ、ソース、認証のメタデータの形式を使用します。

イベントIDは、設定で指定された`daemon.seed`とイベントの順序に対して決定的であるため、同じシードを繰り返すと同じIDが再生されます。`daemon.seed`がない場合、デーモンの起動ごとに独自のセッションが引かれるため、再起動しても前回の実行のIDは繰り返されません。

追加の記録は、RESTとWeb SDK経由のメール/パスワードユーザーによる12件の書き込みをカバーしており、祖先およびマルチパスの書き込みと、失敗した呼び出し後の再配信を含みます。strictプロファイルは記録された本番のメタデータを使用し、emulatorプロファイルは文書化された公式エミュレータのイベント形式を維持します。配信のレイテンシ、再試行のタイミング、ハンドラー間の順序、他のプロバイダー、記録されていない書き込みやハンドラーの形式は、未検証のままです。

- **ルール。** 有限のルールの読み込み、`.validate`、カスケード、`data`/`newData`/`root`とクエリに依存するルールのケース、さらにオーナーとUIDの`.read`および`.write`の評価。70件のルールのケース、さらに7つのルールドキュメント、`query.endBefore`、`query.isOrderByChild()`、`OrderByKey`、`OrderByValue`、`OrderByPriority`、`http.encodeURL()`、呼び出しを伴わないメソッドの読み取り、三項演算子の呼び出し先についての9つのドキュメントと、それらの下での33件の読み取りと書き込みです。

- **Web SDK。** 値のリスナー、キューに入った書き込みを伴う再接続、クエリ単位の購読解除とキャンセルを伴う2つの`orderByChild`ウィンドウのchildとvalueのイベント順序、サーバー値と発火前のルール変更を伴う`onDisconnect`のset、remove、update、cancel、再登録、記録された数値の優先度の子キャンセルのケースと、記録された3つの再登録、ネストした優先度、文字列の優先度の形式、1つのトランザクションスケジュール、WebSocketとロングポーリング上のメール/パスワード認証。追加の記録は、キー、優先度、値の範囲、`equalTo`のウィンドウに対する`prevName`付きのSDKのchildイベント、同値に対するキー付きの境界、親/子のリスナーのファンアウト、存在しないノードとオブジェクトに対するトランザクションと中断されたトランザクション、WebSocketとロングポーリング上のウィンドウと存在しないパスの`get`をカバーします。

### 既知の違い

記録された範囲内では、次の違いが知られています。

- 件数制限のない範囲読み取り、shallow読み取り、PATCHのレスポンスは、公式エミュレータのマップ順序を使用します。4件までのエントリは挿入順を保持し、それより大きなマップはキーのハッシュを使用します。PATCHは、整形出力とコールバック出力を含め、ネストしたレスポンスについて記録されたメンバー順序を保持します。本番との一般的なJSONメンバー順序の一致は主張していません。
- 閉じないままオフラインになったロングポーリングのクライアントは、アイドル状態の接続が切断されるときに`onDisconnect`の書き込みが実行されます。これは最後のリクエストから約100秒から105秒後です。本番は99.3秒から104.0秒後に実行しました。
- `strict`では、イベントストリームは`Connection: close`を持ち、`cancel`イベントとチャンクレスポンスの終了後にHTTP/1.1接続が閉じられます。記録されたイベントのバイト列は本番と一致しますが、記録された本番のレスポンスは転送エンコーディングなしのclose-delimitedでした。一方FireemuはネイティブのHTTP/1.1のチャンクフレーミングを使用します。この転送フレーミングの違いは、オーナーが承認した開発上の例外です（2026-10-31）。イベントの内容、キャンセル、EOFは、既存の証跡の要件の対象のままです。`emulator`プロファイルは既存の接続の挙動を維持します。より広範なストリームのライフサイクルの挙動は、未検証のままです。
- 本番のGoogle署名のFirebase IDトークンは受け付けられません。FireemuのAuthが発行したトークンと`owner`認証情報は受け付けられ、`strict`は他の`gauth`認証情報を、本番の`permission_denied`で拒否します。

### 未検証

上記の有限のREST、ルール、SDK、トリガーのケースが記録されました。それ以外については次のとおりです。

- その他のプッシュIDの形式、サーバー値、クエリ境界、タイムアウト、書き込みサイズのオプションは、未検証のままです。
- 記録されたケースを超えるルールの検証、カスケード、スナップショット、クエリメンバー、クレーム、インデックス診断は、引き続き公式エミュレータを暫定的な基準として使用します。
- 記録されたケースを超えるSDKのイベント、トランザクション、マルチロケーション更新、onDisconnectの形式、サービスアカウントのAdmin認証情報、より広範なFunctionsトリガーの配信とタイミングは、主張していません。

### まだ対応していないもの

- Android、Apple、Unity、およびJavaとPythonのAdmin SDKは、現在のNodeとWebの範囲外です。

### 制限

- 式のネストは最大600レベルです。任意の長さの`&&`、`||`、`+`の連鎖は1回として数えます。これはローカルの安全上の予算であり、公式エミュレータ自体は2,000から4,000レベルの間で失敗します。
- 正規表現エンジンのステップまたは深さの予算を超える`matches()`呼び出しはエラーになり、否定されているかどうかにかかわらず、ルールはfalseになります。
- 書き込みのパスは最大768バイト、データは最大32レベルの深さです。本番の文書化されたとおりです。

### 暫定的な挙動

本番が観測されていない箇所では、記録された公式エミュレータの挙動が暫定的な基準であり、上に挙げた既知の違いの対象となります。これらの比較は、本番との同等性を確立するものではなく、本番の観測後に変更される可能性があります。次のものを対象とします。

- `1.0`のような数値の形式。
- 等しい値の書き込み。
- 優先度。
- 拒否のテキスト。
- ロングポーリングのフレーミング。
- `onDisconnect`の書き込みの結合のされ方。
- 各プロファイルの認証情報。
- 正規表現の方言。
- 書き込みの本文では768バイトのキーを拒否するが、パスでは受け付ける、公式エミュレータの挙動。
- 公式エミュレータが決定性オートマトン化できないパターン。

## 公式エミュレータとの違い

公式エミュレータとの比較は、記録されたケースに限られます。挙げられているサポートされない構文と評価のケースは、ルールの読み込み時に拒否されるか、ルールエラーになります。これは、同等のリソース制限の許可を確立するものではありません。

- 文字クラス（名前、空白、公式エミュレータのリーダーが読み飛ばす書式文字）は、Java 21のテーブルを使用します。
- 演算子とメソッドは、記録されたオペランドの型について、公式エミュレータと比較されました。
- オブジェクトは、公式エミュレータと同様に、アイデンティティで比較されます。`auth`と`query`はそれぞれ自分自身と等しくなります。2つのスナップショットは、ツリーの同じバージョン（`root`と`data`は書き込み前のツリー、`newData`は書き込み後のツリーを読む）を同じ場所で読む場合に等しく、そのため`/t/o`の`data`は`root.child('t').child('o')`と等しく、`newData`とは決して等しくありません。
- 2つのスナップショットの直接比較、または`query`自身との比較は、公式エミュレータと同様に、ルールの読み込み時には引き続き拒否されます。三項演算子がそのチェックをすり抜けさせた場合、比較は実行されます。
- `auth`のメンバーから読み取ったオブジェクトと、子を持つ場所に対して`val()`が返す値は、毎回新しいオブジェクトであり、何とも等しくなりません。

### 正規表現

公式エミュレータは、`matches()`のパターンを、JavaScriptのものでもRE2のものでもない、独自のオートマトン文法の方言で読み取ります。Fireemuは、記録されている箇所ではその文法に従います。たとえば、`a+?`は`(a+)?`を意味し（遅延繰り返しではありません）、`/a|q/`は`.*a|q.*`として検索され、`i`の下では、ASCIIのパターンは公式エミュレータと同様に大文字小文字を同一視し、マッチ対象の文字列はそのままにされます。

Fireemuがまだ再現していない意味を持つ構文要素はエラーになり、否定されているかどうかにかかわらず、ルールはfalseになります。emulatorプロファイルは、以下の構文要素のほとんどを公式エミュレータと同様に読み取ります。strictプロファイルは、本番に問い合わせていないため、そのすべてをエラーのままにします。

| 構文要素 | 例 |
|---|---|
| `(?…)`グループ。emulatorプロファイルはリテラルの`?`で始まるグループとして読み取ります（`/(?:a)/`は`?:a`にマッチします） | `/(?:a)/`, `/(?i)a/` |
| POSIXクラス（どちらのプロファイルも読み取りません） | `/[[:alpha:]]/` |
| 任意の位置の`\W`と`\D`（emulatorプロファイルは読み取ります） | `/\W/`, `/[\D]/` |
| `\d`と`\w`以外のエスケープされた英字または数字（emulatorプロファイルは読み取ります） | `/\n/`, `/\x41/`, `/\1/` |
| クラス内のエスケープされたバックスラッシュ（emulatorプロファイルは読み取ります） | `/[\\a]/` |
| 選択肢の先頭にある演算子、または`^`の後の量指定子（emulatorプロファイルは読み取ります） | `/(|a)/`, `/^(a|*)$/`, `/^*/`, `/^{2}a/` |
| パターンにASCIIを超える文字がある`i`フラグ（どちらのプロファイルも読み取りません） | `/^é$/i`, `/[ａ-ｚ]/i` |
| 改行の前のバックスラッシュ（emulatorプロファイルはラインフィードとして読み取ります） | `/a\`の後に改行、続いて`b/` |
| バックスラッシュの後にU+200Bのような書式文字がある、エスケープされた英字（書式文字は、公式エミュレータと同様に捨てられます） | `/\` U+200B `u0061/` |
| 基本多言語面を超える終端を持つクラスの範囲（emulatorプロファイルはUTF-16単位で読み取ります） | `/[a-😀]/` |

emulatorプロファイルがこれらの構文要素をどう読み取るか。

- `\W`と`\D`は、公式エミュレータのオートマトンと同様に、文字列の言語の補集合です。`\W`は、1つの単語文字を除くすべての文字列なので、`'ab'`と`''`は`/^\W$/`にマッチし、`'a'`はマッチしません。それを含むクラスは、そのメンバーの言語としての和集合（`[\Wa]`）であり、否定されたクラス（`[^\W]`）は、通常どおり単一の文字です。
- `d`、`w`、`D`、`W`以外のエスケープされた英字または数字は、その文字そのものです（`A`は`u0041`、`\b`は`b`であり、そのため`/[\uD800-\uDFFF]/`は、`0`から`u`、`D`、`F`までの文字のクラスです）。
- それ以外は、公式エミュレータのクラス文法を読み取ります。終端が始端より前にある範囲は何も含まず、`[\\a]`は`a`を含み、閉じ括弧の前の`-`は文字であり、選択肢の先頭にある量指定子やその他の演算子は、その文字そのものです。
- パターンをUTF-16単位で読み取るため、基本多言語面を超える文字は2つのクラスメンバーであり、`.`にとっては2単位です。また、バックスラッシュの後では、キャリッジリターン、U+2028、U+2029はラインフィードであり、U+FEFFとU+0085はそれ自身です。

公式エミュレータとstrictプロファイルがパターンを異なって読み取る場合、strictプロファイルはルールを拒否し、決して許可しません。

読み取らないと記した構文要素は、どちらのプロファイルでもエラーのままであるため、emulatorプロファイルは、公式エミュレータがそこで受け付けるものをまだ拒否します。fireemuが拒否し公式エミュレータが許可した、記録された方言コーパスの323行のうち、252行は現在、公式エミュレータと同じ判断をし、71行は拒否されたままです。そのすべてが`i`フラグと非ASCIIテキストを伴うものです（宣言された違いです。Java 21の大文字小文字の畳み込みテーブルが必要になるためです）。

記録された構文上の拒否のケース（`\s`、閉じていないクラスまたはグループ、途中のエスケープされていない`^`を含む）は、ここでは公式エミュレータと同じメッセージで拒否されます。別途記録された決定性オートマトン化のリソースのケースについては、後述します。

公式エミュレータの決定性オートマトン化のリソース制限によって拒否された、記録された8つのパターンも、評価されない式のブランチ内を含め、fireemuがルールを読み込むときに拒否されます。これは、正規表現全体の同等性や本番との同等性を確立するものではありません。これらには、決定性オートマトン化の拒否（"could not determinize efficiently"。公式エミュレータのオートマトンライブラリのリソース制限）が含まれます。記録されたパターンには、1つのパターン内で選択肢のグループを複数回繰り返し指定したものが含まれます。本番の制限は不明であり、これらの比較から本番の挙動は推定されません。

### 孤立サロゲート

- **文字列リテラル内。** 文字列リテラル内の、エスケープされた孤立サロゲート（`'\uD83D'`）は、公式エミュレータと同様に、読み込まれ、UTF-16単位で判定されます（`.length`、`+`、`==`、順序比較、文字列メソッド。カバレッジレポートではU+FFFDとして表示されます）。それを含むパスやキーは何も指さず、`child()`はabsentを読み取り、`hasChild`はfalseになり、インデックスは未定義になります。また、基本多言語面を超える文字を含む文字列の`replace('', to)`は、Javaと同様に、そのペアの2つの半分の間に`to`を置きます。本番はこれらの形式に応答したことがないため、どちらのプロファイルも公式エミュレータに従います。
- **保存される値（emulatorプロファイルのみ）。** JSON文字列値の中の孤立サロゲートのエスケープは、公式エミュレータが保存するのと同様に、孤立サロゲート1つにつき`?`として保存され、有効なペアには手を加えません。これは書き込み本文（`PUT`、`PATCH`、`POST`。ネストした値、`.value`、`.priority`を含む）、WebSocketフレーム、インポートファイルに当てはまり、クエリの境界（`startAt="\ud83d"`、リッスンの`sp`と`ep`）も、同じように`?`として読み取られます。それを含むキーは、どちらのプロファイルでも拒否され、それを含むWebSocketパスには`Invalid token in path`が返されます。strictプロファイルはこれらすべてを従来どおり拒否します。本番には問い合わせていません。
- **トークンのクレームと`authvar`（どちらのプロファイルも読み取りません。宣言された違い）。** これは、クレームに孤立サロゲートを含むトークン（`"x":"\ud83d"`。クレーム名を含む）と、それを含む`gauth`フレームの`authvar`を対象とします。公式エミュレータは、クレーム内のサロゲートをJavaの文字列として保持し（`auth.token.x == '\uD83D'`が成り立ちます）、authvarオブジェクトをそのままエコーします。ここでは、strictプロファイルはそのようなトークンに401を返し、emulatorプロファイルはそのリクエストを匿名として判定し、authvarに孤立サロゲートを含む`gauth`フレームは接続エラーになります。
- **WebSocketのパスとマージキー。** WebSocketフレームのパスの中の孤立サロゲートは、有効なパス（`.priority`を含む）には決してなれません。フレームには`Invalid token in path`が返され、何も書き込み、登録、キャンセルされません。キーが有効なパスではないWebSocketのマージエントリには、emulatorプロファイルでは`invalid_parameters`（`Invalid token in path`、`Empty strings are not valid keys`、またはパスの長さと深さのテキスト）が返されます。strictプロファイルは従来どおり接続エラーを返します。無効な`onDisconnect`のマージエントリのキーは、引き続き接続エラーを引き起こします。

### 評価の予算

1回のルールの評価で2^30単位を超える作業を行うと、ここでもエラーになります。作業は次のように課金されます。

- ルールが読み取り、結合し、比較し、検索し、変換し、置換するすべての文字列について、その長さ。
- クレームまたはネストした値のコピーについて、そのサイズ。
- `child`、`hasChild`、`hasChildren`、`parent()`によって構築または短縮された場所について、そのキーのバイト数。

これにより、二次的な`contains`、長い保存済み文字列の繰り返しの連結、何度も構築し直されるパスが抑えられます。10 MiBの文字列の13回の検索は許可され、50回は収まり、52回は収まりません（既知の制限: ルールは、否定されているかどうかにかかわらず拒否されます）。また、Rulesのコーパスは、1回の評価で最大628単位しか使いません。

予算は評価ごとです。1つのリクエストが多くの評価を実行できる（書き込みは、書き込む子ごとに検証します）ため、リクエスト全体に対する制限や実時間の制限はなく、遅いルールは遅いままです。正規表現のマッチャーには、`matches`の呼び出しごとに200,000ステップという独自の上限があります。

置換、連結、大文字小文字の変換によってルールが構築する文字列が2^26単位（UTF-8の操作は保守的にバイトを数え、UTF-16の操作はコード単位を数えます）を超えると、ここではエラーになり、否定されているかどうかにかかわらず、ルールはfalseになります。これにより、`replace('', '0123456789')`を10回連鎖させるようなルールが、数十ギガバイトを確保するのを防ぎます。公式エミュレータのヒープが独自の制限を決めます。512 MBでは、そのようなステップ7回（約3,900万単位）に応答し、8回目で内部エラー（500）で失敗しました。

### クエリ変数とメソッド

- `query.orderBy`は、どちらのプロファイルでも読み込まれます。読み取りが子で並べ替える場合は子の並べ替え（`query.orderBy == 'a/b'`）、それ以外は`OrderByKey`、`OrderByValue`、`OrderByPriority`です（通常のREST読み取りはキーで、ストリームとリッスンは優先度で並べ替えられます）。書き込み、検証、shallow読み取りではnullです。優先度による並べ替えは、子の`.priority`による並べ替えであるため、そこでは`query.orderBy == '.priority'`と`query.isOrderByChild('.priority')`が成り立ちます。
- `query.endBefore`は排他的な終端の境界であり、`query.isOrderByChild(path)`は読み取りがその子で並べ替えるかどうかです（空のセグメントは破棄されます。セグメントのないパスや無効なキーはエラーです）。
- `http.encodeURL(s)`は、Javaの`URLEncoder.encode(s, "UTF-8")`で、スペースは`%20`、孤立サロゲートは`?`としてエンコードされます。
- 呼び出しを伴わないメソッドの読み取り（`auth.uid.contains`、`data.child`）は、nullではなく何とも等しくない値です。メンバーではない呼び出し先（`(c ? data.child : data.parent)('a')`）は、その型がメソッドを持つ場合に呼び出されます。これは、その型の最初のメソッドがルールの読み込み時にチェックされるためです。そのメソッドが取らない引数の個数での、そのような値を通じた呼び出しは、公式エミュレータは内部エラー（500）で応答しますが、ここでは拒否されます。

最後の3項目に挙げた記録されたすべての形式について、本番は公式エミュレータと同じように応答しました（どちらのプロファイルもそれに従います）。

### 大文字小文字の変換

- Java 21とFireemuの新しいUnicodeテーブルとで大文字小文字の対応が異なる文字を含む文字列の`toLowerCase()`と`toUpperCase()`は、ここではエラーです。対象は、U+019B、U+0264、U+1C89、U+1C8A、U+A7CBからU+A7CF、U+A7D2からU+A7D5、U+A7DAからU+A7DC、および基本多言語面を超えるU+10D50からU+10D65、U+10D70からU+10D85、U+16EA0からU+16EB8、U+16EBBからU+16ED3です。後述の、文脈に依存するシグマの制限も適用されます。
- `Σ`（U+03A3）を含む文字列の`toLowerCase()`は、`Σ`の両隣がそれぞれ文字列の端、スペース、または大文字小文字のあるラテン文字、ギリシャ文字、キリル文字（`'ΑΣ'`、`'ΑΣ Α'`）でない限り、ここではエラーです。Javaは単語境界によって語末形の`ς`を選びますが、Fireemuはこれを再現しないため、`'Α:Σ'`と`'ΑΣ.'`はエラーです。

### 不正なリアルタイムクエリ

不正なリアルタイムのワイヤークエリには、接続を自動的に切断したりクローズフレームを送ったりせずに、接続エラーの制御メッセージが返されます。これらはHTTP 400のレスポンスではなく、リアルタイムプロトコルのレスポンスです。

- 対象には、未知のフィールド、文字列ではないインデックス（`i`）、真偽値ではないinclusiveフラグ（`sin`、`ein`）、文字列ではない件数制限の側（`vf`）、文字列でもnullでもない境界名（`sn`、`en`）、浮動小数点数で書かれた件数制限（`2.0`であっても）が含まれます。
- 型のチェックは、対応する境界や件数制限がない場合でも、フラグ、側、名前に引き続き適用されます。
- nullの境界名は、名前がないことを意味します。他の点で有効なinclusiveフラグや、境界のない名前、件数制限のない側は、効果がありません。
- 指定された整数の件数制限は、正の値で、符号なし32ビットに収まる必要があります。数値ではない件数制限と、その範囲外の整数の件数制限には、代わりに`invalid_parameters`が返されます。
- 指定された件数制限には、側`l`または`r`も必要です。公式エミュレータはどちらの側でもないものとして読み取ることがありますが、Fireemuは側がない、または別の側の場合を拒否します。

### その他の違い

- 識別子の中の`\uXXXX`エスケープは、公式エミュレータが読み取るとおりにデコードされます（`auth.uid`と`auth.uid`は`auth.uid`を指します）。サポートされないその他のJavaScriptの構文要素は、ルールの読み込み時に引き続き失敗します。
- 公式エミュレータがリクエストに内部エラー（500）で応答する場合、Fireemuはそれを拒否します。たとえば、結果的にスナップショットになる値に対する文字列メソッド（`(c ? root : 'a').length`）や、公式エミュレータがパスとして読み取れない場所（`.`、`#`、`$`、`[`、`]`または制御文字を含むキー、`.value`や`.info`のような予約名、途中にある`.priority`、32レベルまたは768バイトを超えるパス）での`getPriority()`です。
- クエリパラメータを複数回指定する、または複数の認証情報（`auth`、`access_token`、`Authorization`ヘッダー）を指定するリクエストは、400で拒否されます。公式エミュレータは最初の値を取り、`auth`を他のものより優先します。
- 両者がともに拒否する一部のルールは、別のメッセージ、または別の列で拒否されます。
