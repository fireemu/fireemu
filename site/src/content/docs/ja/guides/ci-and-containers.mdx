CIジョブでテストをFireemuのもとで実行し、コンテナーからホストや他のコンテナーへエミュレーターを提供し、クライアントが使うホスト名を一覧します。

## GitHub Actionsでテストを実行する

`fireemu exec`はテストコマンドの終了ステータスを返すため、CIジョブに開始と停止の別ステップは必要ありません。

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm ci
      - run: npx fireemu config lint --deny-ineffective
      - run: npx fireemu exec -- npm test
```

FireemuはJavaも起動時のダウンロードも必要としません。npmパッケージが、ランナーのプラットフォーム向けのネイティブバイナリをインストールします。lintステップについては[テストの前に設定を確認する](#テストの前に設定を確認する)で説明します。

### productionExactのジョブを追加する

署名のないテストトークンなど、開発用デフォルトが通してしまうものも確認するには、[`productionExact`](../profiles/)を設定した2つ目の設定ファイル(たとえば`fireemu.production-exact.toml`)で実行するジョブを追加します。

<Tabs syncKey="config-format">
<TabItem label="TOML">

```toml
# Configuration schema version: 1.
schemaVersion = 1
# Compatibility profile: "strict" or "emulator".
profile = "strict"
# Use production behavior for development defaults: true or false; requires strict.
productionExact = true
# Path to Firebase project configuration, relative to this file; a non-empty string.
firebaseJson = "firebase.json"
```

</TabItem>
<TabItem label="JSON">

```json
{
  "schemaVersion": 1,
  "profile": "strict",
  "productionExact": true,
  "firebaseJson": "firebase.json"
}
```

</TabItem>
</Tabs>

```sh
npx fireemu exec --config fireemu.production-exact.toml -- npm test
```

JSON形式の場合は、ファイル名を`fireemu.production-exact.json`にします。

### テストの前に設定を確認する

3つのチェックにより、誤った設定でテストが走る前にジョブを早期に失敗させられます。

```yaml
      - run: npx fireemu config lint --deny-ineffective
      - run: npx fireemu exec --plan --deny-inherited-emulator-env -- npm test
      - run: npx fireemu exec --deny-inherited-emulator-env -- npm test
```

| チェック | 動作 |
|---|---|
| `config lint --deny-ineffective` | 設定に、Fireemuが受け付けるものの読み取らないキーがある場合、終了コード1でジョブを失敗させます。意図して残すキーは`--allow <key>`または`--allow-file <path>`で列挙します([`config lint`](../../reference/cli/#config-lint)を参照)。 |
| `exec --plan` | 実行が解決する内容を表示し、ジョブログにプロジェクトID、サービスとそのポート、読み込まれたファイル、Functionsに使うNode、継承するエミュレーター変数が残るようにします。何も起動せず、実行が、検出できる理由で失敗する場合は終了コード1で終了します。ほかのツールに渡すには`--json`を使います([実行を計画する](../../reference/cli/#実行を計画する)を参照)。 |
| `--deny-inherited-emulator-env` | ジョブの環境に、この実行が起動しないサービスのエミュレーター変数(`PUBSUB_EMULATOR_HOST`、別のスイートの`FIRESTORE_EMULATOR_HOST`など)がある場合、実行を失敗させます。指定しない場合は、警告を出してその変数を残します。意図して設定した変数には`--allow-inherited-emulator-env <NAME>`を使います。 |

### コンテナージョブ

GitHub Actionsの`container:`ジョブや、チェックアウトをバインドマウントしてrootで動くコンテナーでは、チェックアウトの所有者がコンテナーのrootが信頼しないホストユーザーになります。そのため、検出された`fireemu.toml`や`firebase.json`は警告付きでスキップされます。ファイルを明示的に指定するか、チェックアウトを`chown`してください。

```sh
npx fireemu exec --config fireemu.toml --firebase-json firebase.json -- npm test
```

[設定ファイル](../configuration/#ファイル所有者のチェック)を参照してください。

## コンテナーからエミュレーターを提供する

デフォルトではすべてのリスナーがループバック上にあり、公開されたコンテナーのポートからは到達できません。エミュレーターをホストや他のコンテナーに提供するには、次のようにします。

1. `fireemu.toml`の`network.allowNonLoopbackHosts`で有効にします。
2. `firebase.json`で、プロダクトのエミュレーターにホストを指定します。

<Tabs syncKey="config-format">
<TabItem label="TOML">

```toml
# Configuration schema version: 1.
schemaVersion = 1
# Path to Firebase project configuration, relative to this file; a non-empty string.
firebaseJson = "firebase.json"

[network]
# Allow product emulators to bind non-loopback hosts: true or false.
allowNonLoopbackHosts = true
```

</TabItem>
<TabItem label="JSON">

```json
{
  "schemaVersion": 1,
  "firebaseJson": "firebase.json",
  "network": {
    "allowNonLoopbackHosts": true
  }
}
```

</TabItem>
</Tabs>

`firebase.json`では次のようにします。

```json
{
  "emulators": {
    "firestore": { "host": "0.0.0.0", "port": 8080 },
    "auth": { "host": "0.0.0.0", "port": 9099 }
  }
}
```

### ループバック以外でリッスンするもの

- ループバック以外でリッスンできるのは、Firestore、Authentication、Storage、Functions、Eventarc、Cloud Tasks、Pub/Sub、Realtime Databaseだけです。Hub、UI、Loggingエミュレーターはループバックのままです。
- ポートがcontrol APIも兼ねるAuthenticationは、ループバックまたはすべてのインターフェース(`0.0.0.0`または`::`)でリッスンし、それ以外の1つのアドレスではリッスンしません。
- `0.0.0.0`または`::`でのリスナーは、公式CLIと同様に、環境変数とHubでは`127.0.0.1`または`::1`として通知されます。
- このオプションを有効にすると、エミュレーターはComposeのサービス名(`fireemu:8080`)のような単一ラベルの`Host`にも応答します。それ以外の名前は`network.allowedHosts`に列挙する必要があります。[エミュレーターが応答するホスト名](#エミュレーターが応答するホスト名)を参照してください。

### 公開したポートに到達できる相手

:::caution
エミュレーターは認証情報なしで応答します。ポートは、信頼できるネットワークにのみ公開してください。

:::

- 起動時に、ループバック以外のリスナーごとに`warning:`行が表示されます。
- 公開されたポートに到達できるクライアントは、プロダクトのAPIで、ローカルのクライアントができることをすべて行えます。Admin SDKの`Bearer owner`認証情報と、Authエミュレーター独自のルートも含みます。
- Realtime Databaseでは、この中に`database.defaultAccess = "locked"`も含まれます。これは、よく知られた`owner`認証情報を受け付けるため、ループバック以外ではアクセス制御になりません。
- `emulator`プロファイルでは、どのbearerトークンもデータリクエストではRealtime Databaseの管理者となり、その`/.settings/rules.json`は、FirestoreとStorageのルールのルートと同様に、ループバックのピアにのみ応答します。
- ブラウザーのページは引き続きループバックのオリジン(`http://localhost:...`)から来る必要があるため、別のホストから配信されたページは公開されたポートを使えません。

### Fireemu独自のコントロール

- control API、App Checkのデバッグトークン管理、およびFirestore、Storage、Realtime DatabaseのSecurity Rulesを読み込むルートやFirestoreのデータを消去するルートは、ループバックのピアにのみ応答し、それ以外のピアには403を返します。`@firebase/rules-unit-testing`は、`loadFirestoreRules`、`loadStorageRules`、`clearFirestore`を通してルールと消去のルートを呼び出します。
- それらを使うコードは、コンテナーの内部、またはPodmanのpodや`--network container:<name>`のようにネットワーク名前空間を共有するコンテナーの中で実行してください。
- その名前空間内のフォワーダー(`kubectl port-forward`、サイドカープロキシ)はループバックから接続します。そのため、このオプションを有効にすると、control APIへのすべてのリクエストに、プロセスからでもページからでも`Authorization: Bearer <control token>`が必要になります。免除されるのは`/health/`だけです。
- Security Rulesを読み込むルートとFirestoreのデータを消去するルートにはトークンが要求されないため、`@firebase/rules-unit-testing`は引き続き動作します。このようなフォワーダー経由でエミュレーターに到達するクライアントは、公式エミュレーターと同様にそれらを呼び出せます。
- `fireemu exec`は、コマンドにトークンを`FIREEMU_CONTROL_TOKEN`で渡し、`fireemu/testing`とUIもそれを送ります。

## エミュレーターが応答するホスト名

Webページは、読み込み後に、自分が制御する名前を`127.0.0.1`に向け直せます(DNSリバインディング)。するとブラウザーはエミュレーターへのリクエストを同一オリジンとして扱い、`Origin`を送らないため、ページは、エミュレーターが認証情報なしで提供するローカルデータを読み取れてしまいます。

これを防ぐため、プロダクトのエミュレーター(Firestore、Authenticationとcontrol API、Storage、Functions、Eventarc、Cloud Tasks、Pub/Sub、Realtime Database、Hosting)は、`Host`ヘッダーが次のいずれでもないホストを指すHTTP/1リクエストに`403`を返します。

- `localhost`と`.localhost`配下の名前。
- 任意のIPアドレス。そのため、Androidエミュレーターの`10.0.2.2`、LANアドレス、ブリッジアドレスは使えます。
- `.internal`配下の名前。コンテナーランタイムがコンテナーにホスト用として与える名前の予約済みサフィックスです。`host.docker.internal`と`gateway.docker.internal`(Docker)、`host.containers.internal`(Podman)、`host.lima.internal`(LimaとColima)、`host.orb.internal`(OrbStack)。
- `.firebaseio.com`と`.firebasedatabase.app`配下の名前。Realtime Databaseがこれで名前空間を選択します。
- `.cloudworkstations.dev`配下の名前。Firebase StudioとCloud WorkstationsのプレビューURLとポートURLです。
- `.app.github.dev`配下の名前。GitHub Codespacesの転送ポートURLです。
- 特殊用途のサフィックス`.test`、`.local`、`.home.arpa`配下の名前。パブリックDNSは応答しません。`myapp.test`のような`/etc/hosts`のエイリアス、`my-mac.local`のようなmDNS名、デフォルトの`svc.cluster.local`配下のKubernetesサービス名、ホームネットワークの名前です。
- `network.allowNonLoopbackHosts`が有効な場合、Composeのサービス名のような単一ラベルの名前。
- `network.allowedHosts`の名前。

特殊用途と`.internal`の名前は、ローカルの名前解決が信頼できる間だけ安全です。信頼できないネットワークでは、悪意のあるリゾルバー(たとえば公共Wi-FiでDHCPにより配られるもの。RFC 8375の6.1節が`.home.arpa`について指摘するリスク)やLAN上のmDNSピア(`.local`の場合)がそれらに応答し、ページをエミュレーターにリバインドできます。`network.allowedHosts`は名前を追加するだけで、これらのデフォルトを取り除く設定はありません。

チェックの適用方法は次のとおりです。

- `Host`のないリクエスト(HTTP/1.0)とHTTP/2のリクエスト(gRPCクライアント)は、ブラウザーが送らないため、チェックされません。
- 比較では、大文字小文字、ポート、末尾のドット1つを無視します。
- Hub、UI、Loggingエミュレーターは、ループバックの名前にのみ応答します。
- 公式エミュレーターは`Host`をチェックしません。本番には対応するものがないため、このチェックは両方のプロファイルで同じです。
- 拒否されたリクエストには、設定名を示すメッセージ付きの`403`が返り、デーモンは拒否された名前ごとに(最大32名まで)`warning: refused Host "<name>"`行を1行ログに出します。そのため、SDKがレスポンスボディを隠すクライアントでも痕跡が残ります。

### ホスト名を追加する

クライアントが使うその他の名前を追加します。たとえば、トンネル、特殊用途サフィックス以外の`/etc/hosts`の名前、独自のクラスタードメイン配下のKubernetesサービスなどです。エントリは、名前、先頭にドットを付けたそのドメインとすべてのサブドメインを表す名前、またはすべての`Host`に応答する`"*"`(防御をオフにします)のいずれかです。

<Tabs syncKey="config-format">
<TabItem label="TOML">

```toml
[network]
# Allow product emulators to bind non-loopback hosts: true or false.
allowNonLoopbackHosts = true
# Additional accepted host names: exact names, dot-prefixed domains, or "*".
allowedHosts = ["emulator.ci.example", ".corp.example"]
```

</TabItem>
<TabItem label="JSON">

```json
{
  "network": {
    "allowNonLoopbackHosts": true,
    "allowedHosts": ["emulator.ci.example", ".corp.example"]
  }
}
```

</TabItem>
</Tabs>

- エントリにはスキーム、ポート、パスを含めません。
- 名前を列挙しても、その名前を指すリクエストを通すだけです。ブラウザーのオリジンチェックは変わらないため、特権ルートを使うにはページがループバックのオリジンから来る必要があります。
- Fireemuは、`"*"`と、`".com"`のようにトップレベルドメイン全体にあたるエントリについて、起動時に`warning:`行を表示します。そこには任意のWebページが名前を登録できるためです。
- ポリシーはデーモンの起動時に読み込まれます。`network.allowedHosts`を変更したら再起動してください。

### 一般的な環境向けのエントリ

| 環境 | エントリ |
|---|---|
| 独自のクラスタードメイン配下のKubernetesサービス | `".svc.<cluster domain>"`(または正確なサービス名) |
| ngrok | 正確なトンネル名。たとえば`"abc123.ngrok-free.app"` |
| Cloudflare Tunnel | トンネルの正確な公開ホスト名 |
| `.test`、`.local`、`.home.arpa`以外の`/etc/hosts`の名前 | その名前 |

トンネルプロバイダーのドメイン全体ではなく、正確なトンネル名を列挙してください。そのドメイン配下では誰でもトンネルを開けるためです。Firebase Studioの`.cloudworkstations.dev`、Codespacesの`.app.github.dev`、mDNSの`.local`、Kubernetesの`svc.cluster.local`、`.test`の名前にはエントリは不要です。
