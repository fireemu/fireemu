実行中のエミュレーターのデータをディレクトリにエクスポートし、起動時にインポートし、実行の終了時に書き戻します。

## 実行中のエミュレーターからエクスポートする

`fireemu up` の実行中に、別のターミナルで次を実行します。

```sh
npx fireemu emulators:export ./emulator-data
```

`--force` を付けると、空でない出力先を上書きします。

## 起動時にインポートし、終了時にエクスポートする

`--import <dir>` は、起動時にエクスポートを読み込みます。ディレクトリを指定しない `--export-on-exit` は、実行の終了時に状態を同じディレクトリへ書き戻します。

```sh
npx fireemu exec --import ./emulator-data --export-on-exit -- npm test
```

`--import` が受け付けるもの:

- 空の `--import` ディレクトリはデータなしで起動するため、最初の実行に別のコマンドは不要です。
- 存在しないディレクトリは、入力ミスのパスで空のスイートが起動しないように拒否されます。ただし、`--export-on-exit` の書き込み先でもある場合は除きます。
- ファイルはあるが `firebase-export-metadata.json` がないディレクトリは拒否されます。
- Realtime Database のインポートは、どのプロダクトもデータをインストールする前に検証されます。`strict` では、インポートした JSON 文字列値に単独のサロゲートが含まれていると拒否されます。`emulator` プロファイルは、公式エミュレーターと同様に `?` に置き換えます。無効なキーは両方のプロファイルで拒否されます。[Realtime Database のインポート](../../products/realtime-database/#export-import-and-snapshots)を参照してください。

`--export-on-exit` の動作:

- `--export-on-exit` が失敗した場合は `error:` 行として表示され、コマンドが成功していても実行は終了コード 1 で終了します。公式 CLI は警告するだけで終了コード 0 で終了します。保存したデータに依存する CI ジョブが、それなしで成功できないよう、Fireemu は異なる動作にしています。
- エクスポート先ディレクトリは、`/data` にマウントされたコンテナーボリュームのように、ボリュームのマウントポイントでもかまいません。マウントポイントはアトミックなリネームで置き換えられないため、エクスポートはその内部でステージングされてから所定の位置へ移され、古い `firebase-export-metadata.json` が先に消え、新しいものが最後に置かれます。この置き換えはアトミックではありません。エクスポートが中断されると、マニフェストのないディレクトリが残り、`--import` は一部だけを読み込むのではなく、それを拒否します。
- それ以外のディレクトリは、従来どおりアトミックに置き換えられます。

## エクスポート先

永続的な実行を始める前に、ディレクトリの作成や権限の変更をせずに出力先を検査できます。

```sh
npx fireemu doctor --export-dir "$HOME/.local/share/fireemu/emulator-data"
```

Unix 系システムでは、出力先と既存のすべての祖先ディレクトリ(ホームディレクトリを含む)について、所有者と権限が検査されます。それぞれ、自分または root が所有し、他のユーザーが書き込めない必要があります。例外は `/tmp` のような、スティッキービットを持つ root 所有のディレクトリです(macOS では `/tmp` は `/private/tmp` への root 所有のリンクで、これはたどられます)。

- **共有ディレクトリ。** スティッキーディレクトリでは、他のユーザーもエントリを作成できますが、あなたのエントリの名前変更や削除はできないため、`--export-on-exit /tmp/emulator-data` は動作します。ただし、別のユーザーが先にその名前を使うとエクスポートが拒否されることがあるため、共有マシンでは専用の自分のディレクトリを使う方が確実です。`/tmp` 配下では、すでに存在するエクスポートディレクトリは自分のものであり、他のユーザーが書き込めない(`chmod 700`)必要があります。
- **拒否されるもの。** スティッキービットなしで他のユーザーが書き込めるディレクトリ、または他のユーザーのディレクトリ。
- **シンボリックリンク。** エクスポートパス上のすべてのシンボリックリンクが検査されます。たどられるのは、root が所有している場合、または自分が所有していて、自分(または root)だけが書き込めるディレクトリにある場合に限られるため、他のユーザーが `/tmp` に作ったリンクがたどられることはありません。シンボリックリンクの直後の `..` は拒否されます。リンクを含むディレクトリは、祖先と同じ検査に合格する必要があります(所有権を強制するボリューム、他のユーザーへの ACL エントリがないこと)。
- **検査が行われるとき。** `--export-on-exit` は、デーモンまたは子コマンドが起動する前に検査し、権限は変わりうるため、エクスポート時にもう一度検証します。プリフライトから実行の終了まで、エクスポートディレクトリの親を開いたままにするので、その間に名前変更やリンクされたものがたどられることはありません。
- **ボリュームマウント。** ボリュームのマウント先は、その親が書き込み可能である必要がない場合でも、書き込み可能である必要があります。
- **グループ書き込み可能なファイル。** 設定ファイルの探索は、プライベートグループの構成のためにグループ書き込み可能なファイルを許可しますが、エクスポートの公開は、より厳格なクリーンアップの安全規則を維持します。

### macOS

- **ACL。** ACL を持つ祖先ディレクトリは、ACL に所有者、root、エクスポートを実行するユーザー以外に対する `allow` エントリがある場合、そのエントリが示す権限にかかわらず拒否されます(カーネルは `ls -le` に表示されない権利を付与します)。`deny` エントリは受け付けられるため、標準のホームディレクトリ(`group:everyone deny delete` を持つ)とその下のフォルダーは動作します。
- **ACL による拒否の解消。** ACL のためにエクスポートが拒否された場合、メッセージにそのエントリが示されます。それを削除する(`chmod -a`)か、`$TMPDIR` 配下などの別のディレクトリにエクスポートしてください。祖先は `/bin/ls -led <directory>` で確認できます。
- **所有権を無視するボリューム。** 所有権を無視するボリューム(exFAT や FAT のスティックやカード、または「このボリュームの所有権を無視」を有効にした外部 APFS ボリューム)上の出力先は、ディレクトリの所有者とモードから誰が変更できるかが分からないため拒否されます。所有権を強制するボリュームにエクスポートしてください。
- **アトミックなリネームがないボリューム。** アトミックなディレクトリのリネームがないボリューム(exFAT、FAT、一部のネットワークファイルシステム)でもエクスポートは公開できません。APFS ボリューム上のディレクトリを使ってください。

### Windows

`emulators:export` と `--export-on-exit` は現在利用できません。インポートとその他のエミュレーターは動作します。

## 独立したテストワールドをエクスポートする

[テストワールド](../test-worlds/)では、`hub: true` により、ワールドの既存の CLI エクスポートコマンド用のプライベート Hub が有効になります。`world.directory` の外にある、呼び出し側が所有する絶対パスのエクスポート先を使ってください。

```js
import { resolve } from 'node:path';
import { createTestWorld } from 'fireemu/testing';

const exportPath = resolve('./emulator-data');
const services = ['auth', 'firestore', 'storage'];
const world = await createTestWorld({ services, hub: true });
try {
  await world.run('fireemu', [
    'emulators:export', exportPath, '--project', world.projectId,
  ]);
} finally {
  await world.dispose();
}
const restored = await createTestWorld({ services, import: exportPath });
try {
  // Connect fresh SDK clients through restored.endpoints or restored.run(...).
} finally {
  await restored.dispose();
}
```

- `--project` は明示的に渡してください。
- ヘルパーは、Hub の OS が割り当てるポートとプライベートロケーターを所有します。同じプロジェクトのワールドは独立したままです。
- 開発用バイナリでは、`binaryPath` とエクスポートコマンドの両方に、その絶対パスを使ってください。
- インポートは作成時にスナップショットされるため、元のエクスポートを後から編集しても、リセットには影響しません。
- ワールドディレクトリの外のエクスポートは、破棄後も呼び出し側の所有のままです。

[エクスポートとインポートの完全なガイド](https://github.com/fireemu/fireemu/blob/main/docs/test-worlds.md#export-and-import-test-data)を参照してください。

## エクスポートが保持するもの

| 保持される | 保持されない |
| --- | --- |
| Auth のユーザーとパスワード認証情報 | App Check の状態 |
| Firestore のドキュメント | 仮想クロック |
| Storage のバイト列とメタデータ | Functions のプロセスメモリ |
| Realtime Database のデータ | 過去に発行されたトークンの有効性 |
