`fireemu`パッケージを開発依存として追加し、`fireemu.toml`を作成すれば、すぐエミュレータの起動やテスト実行を始められます。

## 始める前に

- **Node.js 20以降**（パッケージの`engines`は`>=20`）：`fireemu`ランチャーとNode.js用Functionsランナーの実行に必要です。
- **対応プラットフォーム**：OSとアーキテクチャに合ったビルド済みバイナリが自動で入ります。Javaランタイムは不要です。

| OS | アーキテクチャ |
|---|---|
| macOS 13以降 | Apple silicon、Intel |
| Linux（Alpine・distrolessを含むglibc/musl環境） | x86-64、arm64 |
| Windows 10以降 | x86-64 |

Node.jsのCloud Functionsを動かすには、コードベースに`firebase-functions` v6またはv7が必要です。Pythonコードベースの場合は、Python 3.10〜3.14と`firebase-functions`を導入した専用`venv`を用意してください（macOS/Linux対応。詳しくは[Cloud Functions（Python）](../../products/functions-python/)を参照）。

## インストール

プロジェクトの開発依存にFireemuを追加します。

```sh
npm install --save-dev fireemu
```

## `fireemu.toml`を作成する

```sh
npx fireemu init
```

`init`はカレントディレクトリに`fireemu.toml`を作成します。対話形式で使用する[互換性プロファイル](../../guides/profiles/)（既定の`strict`を推奨）と、既存の`firebase.json`を参照するかどうかを確認します。参照を選んでもコピーは作らず、起動のたびに`firebase.json`からSecurity Rules・インデックス・Functionsコードベース・ポート設定を直接読み込みます。

CIやスクリプトでは対話を省略できます。

```sh
npx fireemu init --yes
```

既存の`fireemu.toml`は`--force`を付けない限り上書きされません。`fireemu.json`が残っている場合は、先に削除してから作成してください。

`npx fireemu init --yes`は次の内容を生成します（説明用のコメントを添えています）。

JSONタブは同等の`fireemu.json`の書き方です（`init`が書き出すのはTOMLのみです）。

`./firebase.json`が存在するか`--firebase-json <file>`を渡した場合、`init`は`firebaseJson = "firebase.json"`を自動で追記します。これにより、ポート・ルール・インデックス・Functionsコードベースがそのファイルから読み込まれます。

設定キーの一覧は[設定のスキーマ](../../reference/configuration/)を参照してください。`npx fireemu init --reference`を実行すると、全キーの解説コメント付きで`fireemu.reference.toml`を書き出せます（この参照用ファイルは実行時には読み込まれません）。

## エミュレータを起動する

```sh
npx fireemu up
```

`up`は`Ctrl+C`で止めるまでエミュレータを起動したままにします。ブラウザで`http://127.0.0.1:4000/ui/`を開くと[Emulator UI](../../guides/ui/)からデータの閲覧・編集や仮想時計の操作ができます。

起動時の出力冒頭には、読み込んだ設定ファイルと、Firestore/StorageのSecurity Rulesが有効になっているかが表示されます。

## エミュレータに対してコマンドを実行する

テストスイートなど、特定コマンドの実行中だけエミュレータを動かしたいときは`exec`を使います。

```sh
npx fireemu exec -- npm test
```

`exec`は次の流れで動作します。

1. 対象のエミュレータを起動します。
2. すべてのリスナーの準備が完了すると、Firebase SDKのエミュレータ用環境変数を設定してコマンドを実行します（[アプリを接続する](../connect/)を参照）。
3. コマンドが終わったらエミュレータをすべて停止します。
4. 実行したコマンドの終了コードをそのまま返します。

Unix環境では`SIGINT`と`SIGTERM`が子コマンドへ転送されます。`exec`では`--ui`を付けない限りEmulator UIは起動しません。

Firebase CLIと同じコマンド名もエイリアスとして使えます。

```sh
npx fireemu emulators:start
npx fireemu emulators:exec -- npm test
```

## 起動するサービスを選ぶ

既定ではFirestore、Authentication、Storage、App Checkが起動します。その他のサービスは設定がある場合に起動します。

| サービス | 自動起動する条件 |
|---|---|
| Functions（Eventarc・Cloud Tasksを含む） | コードベースが設定されている |
| Pub/Sub | `emulators.pubsub`、`daemon.pubsubPort`、`--pubsub-port`のいずれかが設定されている |
| Realtime Database | `emulators.database`、`daemon.databasePort`、`--database-port`のいずれかが設定されている |
| Hosting | `firebase.json`に`hosting.public`ディレクトリが設定されている |

`--only`で起動するサービスを明示的に絞ることもできます。

```sh
npx fireemu up --only auth,firestore,storage
npx fireemu exec --only firestore -- npm test

# 特定のFunctionsコードベースだけ起動
npx fireemu up --only functions:<codebase>
```

## デフォルトポート

FireemuはFirebase Local Emulator Suiteと同じ既定ポートを使います。`firebase.json`やコマンドラインオプションで指定したポートが優先されます。

| サービス | ポート | オプション |
|---|---|---|
| Emulator UI | 4000 | `--ui-port` |
| Emulator Hub | 4400 | `--hub-port` |
| Logging | 4500 | `--logging-port` |
| Firebase Hosting | 5000 | `--hosting-port` |
| Cloud Functions | 5001 | `--functions-port` |
| Cloud Firestore | 8080 | `--firestore-port` |
| Cloud Pub/Sub | 8085 | `--pubsub-port` |
| Realtime Database | 9000 | `--database-port` |
| Authentication | 9099 | `--http-port` |
| Cloud Storage | 9199 | `--storage-port` |
| Eventarc | 9299 | `--eventarc-port` |
| Cloud Tasks | 9499 | `--tasks-port` |

## ヘルプを見る

各サブコマンドのオプション一覧は`--help`で確認できます。

```sh
npx fireemu --help
npx fireemu exec --help
```

起動しないときは`npx fireemu doctor`を実行し、[トラブルシューティング](../../guides/troubleshooting/)も参照してください。
