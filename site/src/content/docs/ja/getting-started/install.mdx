npmパッケージ`fireemu`をインストールし、`fireemu.toml`を作成してから、エミュレータを起動するか、エミュレータに対してコマンドを実行します。

## 始める前に

- **Node.js 20以降**(パッケージの`engines`フィールドは`>=20`です)。`fireemu`ランチャーとFunctionsランナーを実行します。
- **対応プラットフォーム。** パッケージはお使いのプラットフォーム向けのビルド済みバイナリをインストールします。Javaなどのランタイムは不要です。

| OS | アーキテクチャ |
|---|---|
| macOS 13以降 | Apple silicon、Intel |
| Linux(Alpineやdistrolessなどglibcまたはmuslのどのディストリビューションでも) | x86-64、arm64 |
| Windows 10以降 | x86-64 |

Cloud Functionsを実行するには、コードベースに`firebase-functions` v6またはv7も必要です。Pythonのコードベースでは、Python 3.10から3.14と、`firebase-functions`を入れた専用の`venv`が代わりに必要です(macOSとLinux。[Cloud Functions](../../products/functions-python/)を参照)。

## インストール

Fireemuをプロジェクトの開発依存として追加します。

```sh
npm install --save-dev fireemu
```

## `fireemu.toml`を作成する

```sh
npx fireemu init
```

`init`は、カレントディレクトリに`fireemu.toml`を作成します。対話モードでは、どの[互換性プロファイル](../../guides/profiles/)を使うか(デフォルトの`strict`を推奨します)と、既存の`firebase.json`を再利用するかを尋ねます。再利用する場合、Fireemuはファイルをコピーせず参照します。Security Rules、インデックス、Functionsのコードベース、ポートは、Fireemuが起動するたびにそのファイルから読み込まれます。

CIやスクリプトでは、非対話形式を使います。

```sh
npx fireemu init --yes
```

既存の`fireemu.toml`は、`--force`を指定しない限り上書きされません。既存の`fireemu.json`は保持されます。`fireemu.toml`を作成する前に削除してください。

`npx fireemu init --yes`は、次のファイルをそのまま書き出します(各行の説明のため、ここではコメントを追加しています)。

JSONタブは同等の`fireemu.json`で、`init`はこれを書き出しません。

`./firebase.json`が存在する場合(または`--firebase-json <file>`を指定した場合)、`init`はそれを参照し、`firebaseJson = "firebase.json"`の1行を追加します。これにより、ポート、Security Rules、インデックス、Functionsのコードベースがそのファイルから読み込まれます。

すべてのキーは[設定スキーマ](../../reference/configuration/)に一覧があります。`npx fireemu init --reference`は、すべてのキーを説明する`fireemu.reference.toml`も書き出します。このファイルは読み込まれません。

## エミュレータを起動する

```sh
npx fireemu up
```

`up`は、`Ctrl+C`を押すまでエミュレータを実行し続けます。`http://127.0.0.1:4000/ui/`で[Emulator UI](../../guides/ui/)を開くと、データを確認・管理できます。

起動時の出力の最初の数行には、読み込まれた設定ファイルの名前と、FirestoreとStorageについてSecurity Rulesが読み込まれているかどうかが表示されます。

## エミュレータに対してコマンドを実行する

テストスイートなど、コマンドの実行中だけエミュレータを動かすには`exec`を使います。

```sh
npx fireemu exec -- npm test
```

`exec`は次の4つを行います。

1. エミュレータを起動します。
2. すべてのリスナーの準備ができたら、Firebase SDKのエミュレータ環境変数を設定してコマンドを1回実行します([アプリを接続する](../connect/)を参照)。
3. コマンドが終了したら、すべてを停止します。
4. コマンドの終了ステータスで終了します。

Unixでは、`SIGINT`と`SIGTERM`がコマンドに転送されます。`exec`は、`--ui`を付けない限りUIを起動しません。

公式のコマンド名もエイリアスとして使えます。

```sh
npx fireemu emulators:start
npx fireemu emulators:exec -- npm test
```

## サービスを選ぶ

Firestore、Authentication、Storage、App Checkはデフォルトで起動します。そのほかのサービスは、設定されている場合にのみ起動します。

| サービス | 起動する条件 |
|---|---|
| Functions(およびEventarcとCloud Tasks) | コードベースが設定されている |
| Pub/Sub | `emulators.pubsub`、`daemon.pubsubPort`、`--pubsub-port`のいずれかが設定されている |
| Realtime Database | `emulators.database`、`daemon.databasePort`、`--database-port`のいずれかが設定されている |
| Hosting | `firebase.json`に`hosting.public`ディレクトリがある |

`--only`で、どのサービスを起動するかを正確に指定できます。

```sh
npx fireemu up --only auth,firestore,storage
npx fireemu exec --only firestore -- npm test

# One Functions codebase
npx fireemu up --only functions:<codebase>
```

## デフォルトポート

FireemuはLocal Emulator Suiteと同じデフォルトポートを使います。`firebase.json`またはコマンドラインで指定したポートが優先されます。

| サービス | ポート | オプション |
|---|---|---|
| Emulator UI | 4000 | `--ui-port` |
| Emulator Hub | 4400 | `--hub-port` |
| Logging | 4500 | `--logging-port` |
| Firebase Hosting | 5000 | `--hosting-port` |
| Cloud Functions | 5001 | `--functions-port` |
| Cloud Firestore | 8080 | `--firestore-port` |
| Cloud Pub/Sub | 8085 | `--pubsub-port` |
| Realtime Database | 9000 | `--database-port` |
| Authentication | 9099 | `--http-port` |
| Cloud Storage | 9199 | `--storage-port` |
| Eventarc | 9299 | `--eventarc-port` |
| Cloud Tasks | 9499 | `--tasks-port` |

## ヘルプを見る

すべてのコマンドは、オプションを説明するヘルプを備えています。

```sh
npx fireemu --help
npx fireemu exec --help
```

エミュレータが起動しない場合は、`npx fireemu doctor`を実行してください。[トラブルシューティング](../../guides/troubleshooting/)を参照してください。
