Install `fireemu` as a dev dependency, create `fireemu.toml`, and start the emulators or wrap your test command with `exec`.

## Before you start

- **Node.js 20 or newer** (`engines.node` is `>=20`) to run the `fireemu` CLI launcher and Node.js Functions runner.
- **Supported platforms**: npm installs a prebuilt native binary for your platform, with no Java runtime needed.

| OS | Architecture |
|---|---|
| macOS 13 or newer | Apple silicon, Intel |
| Linux (glibc or musl, including Alpine and distroless) | x86-64, arm64 |
| Windows 10 or newer | x86-64 |

To run Node.js Cloud Functions, install `firebase-functions` v6 or v7 in your Functions codebase. Python codebases need Python 3.10–3.14 in a `venv` with `firebase-functions` installed (macOS and Linux; see [Cloud Functions (Python)](../../products/functions-python/)).

## Install

<Tabs syncKey="install-method">
<TabItem label="npm">

Add Fireemu to your project's devDependencies (includes the CLI plus `fireemu/testing`, `fireemu/vitest`, `fireemu/playwright`, and `fireemu/control`):

```sh
npm install --save-dev fireemu
```

</TabItem>
<TabItem label="Nix (Flakes)">

Install the standalone `fireemu` CLI binary (with the bundled Emulator UI and Functions runners) via Nix flakes:

```sh
# Install into your profile
nix profile install github:fireemu/fireemu

# Or run directly without installing
nix run github:fireemu/fireemu -- --version
```

In a project `flake.nix`, add `fireemu.url = "github:fireemu/fireemu";` and include `inputs.fireemu.packages.${system}.default` in your `devShell`.

> **Note:** Nix provides the `fireemu` CLI binary. If your test suite imports `fireemu/testing`, `fireemu/vitest`, or `fireemu/playwright`, install the `fireemu` npm package as well (you can point it at the Nix binary with `FIREEMU_BINARY_PATH=$(which fireemu)`).

</TabItem>
</Tabs>

## Create `fireemu.toml`

```sh
npx fireemu init
```

`init` writes `fireemu.toml` in the current directory. In interactive mode it asks which [compatibility profile](../../guides/profiles/) to use (`strict` is the default and recommended) and whether to reference an existing `firebase.json`. Referencing `firebase.json` does not copy it: Security Rules, indexes, Functions codebases, and ports are read straight from `firebase.json` on every start.

For scripts and CI, skip the prompts:

```sh
npx fireemu init --yes
```

An existing `fireemu.toml` is left alone unless you pass `--force`. If a `fireemu.json` already exists, remove it before creating `fireemu.toml`.

`npx fireemu init --yes` generates this file (comments added here to explain each line):

<Tabs syncKey="config-format">
<TabItem label="TOML">

```toml
# Editor hint: points TOML-aware editors at the JSON Schema for completion and validation.
#:schema https://raw.githubusercontent.com/fireemu/fireemu/main/spec/config/fireemu.schema.json
# The configuration format version. The only value is 1.
schemaVersion = 1
# "strict" follows production (the default and recommended); "emulator" follows the pinned official emulator.
profile = "strict"
# The same schema URL as a data key, so JSON-oriented tools find it.
"$schema" = "https://raw.githubusercontent.com/fireemu/fireemu/main/spec/config/fireemu.schema.json"
# "native" (Firestore Native mode API) or "mongodb-compatible".
firestore.apiMode = "native"
# "standard" or "enterprise".
firestore.edition = "standard"
```

</TabItem>
<TabItem label="JSON">

```json
{
  "schemaVersion": 1,
  "profile": "strict",
  "$schema": "https://raw.githubusercontent.com/fireemu/fireemu/main/spec/config/fireemu.schema.json",
  "firestore": {
    "edition": "standard",
    "apiMode": "native"
  }
}
```

</TabItem>
</Tabs>

The JSON tab shows the equivalent `fireemu.json` format (note that `init` only writes TOML).

When `init` runs without prompts (`--yes`, `--no-interactive` or no terminal) and `./firebase.json` exists, it references that file with `firebaseJson = "firebase.json"`; an interactive run asks first. With `--firebase-json <file>`, `firebaseJson` holds the path you pass. Ports, Security Rules, indexes and Functions codebases are then read from that file.

See the [configuration schema](../../reference/configuration/) for every available key, or run `npx fireemu init --reference` to generate a commented `fireemu.reference.toml` (Fireemu never loads the reference file).

## Start the emulators

```sh
npx fireemu up
```

`up` keeps the emulators running until you press `Ctrl+C`. Open the [Emulator UI](../../guides/ui/) at `http://127.0.0.1:4000/ui/` to browse data, check logs, and control the clock.

The startup banner prints which configuration files were loaded and whether Firestore and Storage Security Rules are active.

## Run a command against the emulators

Use `exec` when you want Fireemu to run only for the lifetime of a command, such as a test suite:

```sh
npx fireemu exec -- npm test
```

`exec` handles the full lifecycle:

1. Starts the selected emulators.
2. Once every listener is ready, runs your command with the Firebase SDK emulator environment variables set ([Connect your app](../connect/)).
3. Shuts down all emulators when the command finishes.
4. Exits with your command's exit code.

On Unix, `SIGINT` and `SIGTERM` are forwarded to the child command. `exec` skips the Emulator UI unless you pass `--ui`.

The Firebase CLI command names also work as aliases:

```sh
npx fireemu emulators:start
npx fireemu emulators:exec -- npm test
```

## Choose services

Firestore, Authentication, Storage, and App Check start by default. Other services start when configured:

| Service | Starts automatically when |
|---|---|
| Functions (along with Eventarc and Cloud Tasks) | A codebase is configured |
| Pub/Sub | `emulators.pubsub`, `daemon.pubsubPort`, or `--pubsub-port` is set |
| Realtime Database | `emulators.database`, `daemon.databasePort`, or `--database-port` is set |
| Hosting | `firebase.json` defines a `hosting.public` directory |

Pass `--only` to pick the exact set of services to run:

```sh
npx fireemu up --only auth,firestore,storage
npx fireemu exec --only firestore -- npm test

# Start a single Functions codebase
npx fireemu up --only functions:<codebase>
```

## Default ports

Fireemu uses the same default ports as the Firebase Local Emulator Suite. Ports in `firebase.json` or CLI flags override these defaults.

| Service | Port | Flag |
|---|---|---|
| Emulator UI | 4000 | `--ui-port` |
| Emulator Hub | 4400 | `--hub-port` |
| Logging | 4500 | `--logging-port` |
| Firebase Hosting | 5000 | `--hosting-port` |
| Cloud Functions | 5001 | `--functions-port` |
| Cloud Firestore | 8080 | `--firestore-port` |
| Cloud Pub/Sub | 8085 | `--pubsub-port` |
| Realtime Database | 9000 | `--database-port` |
| Authentication | 9099 | `--http-port` |
| Cloud Storage | 9199 | `--storage-port` |
| Eventarc | 9299 | `--eventarc-port` |
| Cloud Tasks | 9499 | `--tasks-port` |

## Get help

Every subcommand prints its full flag reference with `--help`:

```sh
npx fireemu --help
npx fireemu exec --help
```

If startup fails, run `npx fireemu doctor` and see [Troubleshooting](../../guides/troubleshooting/).
