### Compatibility claim

Under the `emulator` profile and the evidence recorded in [`spec/compatibility/contract.json`](https://github.com/fireemu/fireemu/blob/main/spec/compatibility/contract.json), Fireemu claims compatibility with the Local Emulator Suite products it serves with parity in `firebase-tools` 15.28.2: Cloud Firestore, Firebase Authentication, Cloud Storage for Firebase, Cloud Functions, Cloud Pub/Sub, and Eventarc, including Security Rules on Firestore and Storage. It makes no complete-suite or unqualified superset claim because:

- Realtime Database and Firebase Hosting are served without a parity claim against the official emulator (both are verified against production for recorded cases);
- App Hosting and Data Connect are deferred;
- Firebase Extensions is not planned.

## Fireemu, the official emulator and production

These are the behavioral differences most likely to change a test outcome. The Fireemu column reflects the default `strict` profile.

| Behavior | Production | Official emulator | Fireemu |
|---|---|---|---|
| Query missing a composite index | Refused | Runs | Refused (`firestore.missingIndexes = "report"` runs the query and reports the missing index) |
| Firestore client request to a project with no Security Rules | Refused | Allowed | Refused |
| TOTP multi-factor authentication | Supported | Not available | Supported via project MFA configuration |
| Request naming a non-existent tenant | Refused | Creates the tenant | Refused |
| `beforeEmailSent` blocking function | Runs | Not run | Runs |
| App Check | Supported | Not available | Debug tokens (no real attestation or replay protection) |
| Scheduled functions | Triggered on the Cloud Scheduler schedule | Not run on a schedule | Run on a virtual clock you control |
| Unsigned mock ID tokens in Security Rules | Refused | Accepted | Accepted by default; refused with `productionExact` |
| Declared Storage upload checksums | Verified | Not verified | Verified |

## Production verification

Fireemu checks its responses against recordings captured from real Firebase projects.

- **Verified against production**: every condition in the area's frozen inventory matches the production recording, or differs only in a reviewed and documented known difference.
- **In progress**: work is still underway; counts reflect recorded conditions rather than full verification of the area.
