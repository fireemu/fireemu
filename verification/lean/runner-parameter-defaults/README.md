# Runner parameter defaults in Lean 4

The reference models declaration-order resolution over an explicit own-property string environment. Existing values, including empty strings, take precedence. Each ordinary absent parameter may read earlier assignments through a default expression. A failed or unsupported default records a missing parameter and leaves it absent for later declarations. Secret and empty-name declarations do not evaluate their defaults.

Theorems prove that one declaration and an entire declaration sequence preserve existing values. They also pin the observable differences caused by ordering and a failing default followed by a duplicate declaration. Static defaults enter the model as their serialized text. Replay uses real JavaScript strings, an integer, a boolean, an array, an unsupported object and a throwing expression, both directly and through the SDK declaration hook. General JavaScript object or expression evaluation is outside the model.

From this directory, regenerate the corpus as follows.

~~~sh
lake build
lake exe corpus > ../../../tools/runner-node/tests/fixtures/lean-runner-parameter-defaults.corpus
cd ../../..
node --test tools/runner-node/runner-parameter-defaults-lean-corpus.test.mjs
~~~
